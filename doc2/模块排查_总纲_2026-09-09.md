## 三、体检清单（每模块对照扫）

- **A 资源/生命周期**：new/delete 配对、句柄/HANDLE 释放（含异常/早退路径）、COM 引用计数、线程 join、资源在错误分支泄漏
- **B 并发**：文件级 static / 全局可变状态、无锁 RMW、锁序是否成环、shared_ptr 跨线程、thread_local 误用（对照 P1-14 ORB 教训）
- **C 边界/输入**：buffer 越界、整数溢出/符号、空指针解引用、除零、超大输入、空串/空图、并发同调（对照 P1-15 Wgc 教训）
- **D 返回码/错误处理**：谎报成功、异常被吞且无日志、失败后内部状态残留、重试语义（对照 P1-10 UnBind 教训）
- **E 日志**：刷屏无节流、无级别、假日志、敏感信息
- **F 死代码/过时**：未用函数/字段/整文件、TODO/FIXME、与实现不符的注释（对照 P2 教训：删除前先查真实调用链）
- **G API 语义**：字符串出参（CopyOutBstr 约定）、错误码与文档一致性、NULL 入参处理（对照 L3 教训）
- **H 性能**：热路径大拷贝、每帧重算、锁粒度过大、容器无 reserve

## 四、排查顺序建议（严格金字塔序 · 用户拍板 2026-09-09）

每层清完再上爬；层内按"被依赖者先查"。闭环模块（capture/ocr/com）同层连带验证不重查。

| 批 | 层 | 模块（→=查序） | 说明 | 状态 |
|---|---|---|---|---|
| 批 1 | 基座层 | base → memory → network → algorithm → ipc | base 被全库依赖最先查 | ☐ |
| 批 2 | 服务层 | hook → input → window → capture → image | capture 已闭环仅连带验；input 顺带解 MouseKey 挂起 | ☐ |
| 批 3 | 引擎层 | opencv → ocr → yolo | ocr 闭环维持；yolo E 组挂起不动 | ☐ |
| 批 4 | 出口层 | binding → op → com → c_api | com 闭环复核；c_api 1475 行收口 | ☐ |

> 依赖图非纯 DAG，两处向上引用需留意：**hook→capture、image→ocr**（实扫 include 得出）——查这两模块时其反向依赖目标须已稳（capture/ocr 均已闭环，不影响开工）。
