## 二、构建链四件套（与 x64 的差异点）

1. **OpenCV x86**（`_wb_build_opencv_x86.py`）：配置必须与 x64 现役对齐——
   `WITH_ITT/WEBP/TIFF/OPENJPEG/JASPER=OFF` + `/MD`。任何一项缺失即对应 LNK2019
   （ittnotify 符号 / WebP mux / `_jas_*`）。产物 14 个 .lib 与 x64 清单一致。
2. **MinHook x86**（`_wb_build_minhook_x86.py`）：1.3.4 的 `cmake_minimum_required` 过老，
   CMP0091 OLD 忽略 `CMAKE_MSVC_RUNTIME_LIBRARY` → 必须直接写
   `CMAKE_{C,CXX}_FLAGS_RELEASE=/MT /O2 /Ob2 /DNDEBUG`。验证：.lib 中 MSVCRT 引用 4→0。
3. **op x86**（`_wb_build_op_x86.py`）：
   - `/MD` 主运行库 + `/NODEFAULTLIB:MSVCRT`（SHARED+EXE）。
     **x86 SEH 专属断链**：`MSVCRT.lib(chandler4gs.obj)` 的 `__except_handler4_common`
     仅 x86 存在；纯 /MT 静态 CRT 自洽无需 MSVCRT → 忽略之即通过，且产物不依赖 VC 运行时 DLL。
   - configure 每次必跑（幂等，防陈旧 CMakeCache 参数残留）。
4. **C API 裸名导出**：x86 `__stdcall` 导出名带 `_Name@N` 装饰（`extern "C"` 不消），
   上游/探针按裸名 `GetProcAddress("OpCreate")` 拿不到 → `libop/CMakeLists.txt` 在 x86 下
   从 `include/op_c_api.h` 正则自动生成 `.def`（256 个裸名 EXPORTS）挂给 `op_c_api` 目标。

## 三、ONNX 条件化（x64 行为不变）

Microsoft 不发布 32 位 onnxruntime 包，x86 编不过 → `OP_HAS_ONNX` 按位数探测：
- CMake 按「本架构有无 onnxruntime 包」探测，x64 恒 1；x86=0 时从源列表剔除
  `OnnxOcrEngine.cpp`/`OnnxYoloEngine.cpp`，宏透传各目标。
- 两个 Onnx 头整类包 `#if defined(OP_HAS_ONNX) && OP_HAS_ONNX`；
  `OcrService`/`YoloDetector` 的所有 `Onnx*Engine` 引用点补**编译期**守卫
  （不只是运行期判空——x86 编译期也不能见到该类型）。

## 四、OpContext 布局错位（x86 独发，ODR 级）

此前只给 `binding/BindingSession.cpp` 等个别文件单独加 `/std:c++20`。不同 C++ 标准下
MSVC STL 布局有差异 → `OpContext.cpp`（默认标准）构造的对象与 `OpRuntime.cpp` 读取的
成员偏移错位，**x86 实测 curr_path 差 24 字节 → OpGetPath 必崩**。修复 = libop 目标统一
`CXX_STANDARD 20`（x64 本就经全局 `-std:c++20` 生效，此项对 x64 无行为变化）。

## 五、排查教训（最重要）

1. **cdecl 调 stdcall = 每次带参调用栈漂移 4 字节** → 垃圾返回值 + 延迟崩溃，
   症状极像 DLL bug，实为探针 bug。x86 DLL 本身自始至终没有 bug。
   正确 typedef 形式（括号包住 `__stdcall *`）：
   ```c
   typedef void *(__stdcall *OpCreate_t)(void);
   typedef const wchar_t *(__stdcall *OpGetPath_t)(void *);
   ```
   写成 `void *__stdcall (*T)(void)` 语法错；丢了 `__stdcall` 则踩上述坑。
   **一个文件里漏一处（如 OpGetBasePath_t）就足够让后续调用全崩。**
2. **探针必须与 DLL 同位数**：64 位探针加载 x86 DLL = err 193（BAD_EXE_FORMAT），
   不是 DLL 问题。
3. **MSVC 宿主路径**：VS 装在 `D:\Program Files\...\Professional`（不是 C 盘 Community）；
   Git Bash 调 cl 必须 `MSYS_NO_PATHCONV=1`。
