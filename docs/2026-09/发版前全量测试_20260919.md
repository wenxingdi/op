## 3. 真机执行结果

### 3.1 WgcTest：4 PASS / 6 FAILED —— 判定为**环境限制**

失败 6 个用例全部绑定 `normal.wgc` / `normal.auto`（WGC 后端）；PASS 的 4 个均为普通
`normal`（GDI/DXGI）路径。根因日志：

```
WgcCapture::Init SEH fault code=0xC0000005 hwnd=... -- WGC broken in this process,
subsequent WGC requests will fail fast
BindEx: WGC broken by previous in-process SEH fault on Windows 10, bind skipped
```

- **仅 1 个真实故障**（首次 `WgcCapture::Init` 触发 SEH 访问违例），其余 5 个是 op 的
  **fail-fast 保护**短路产生的级联失败——保护机制本身工作正常（套件 11s 内正常跑完，无挂起）。
- **环境归因**：本机装有 4 个虚拟显示器驱动（向日葵 `OrayIddDriver`、`GameViewer Virtual
  Display`、`USB Mobile Monitor Virtual Display` ×2），WGC 在虚拟显示/远程控制场景下不可用是已知限制。
  同为注入式截图的 `dx.d3d12`（R3）在本机 **全 PASS**，反证问题出在 WGC 自身而非 op 的捕获框架。
- **处置**：不计入发版阻断；需在**无虚拟显示驱动的机器**上复测 WgcTest 取得有效判据。

### 5.2 `OpDestroy` 违例结案：工具变量遮蔽，非产品缺陷

真因：`workbench/probes/ocr_bench.py` 的图片校验循环中 `h = struct.unpack('<i', d[22:26])[0]`
把外层 OCR 句柄 `h` **覆盖成图像高度**，随后 `OpDestroy(h)` 实际传入 `13`——
崩溃地址 `0x0D` 与 `client0.bmp` 高度精确吻合。已修（循环变量改名 `ih`）。

> 教训：临时探针的变量遮蔽会让"疑似产品缺陷"污染根因判断；
> 同类问题另有本次抽查中漏设 `restype = c_void_p` 导致 64 位句柄被截断为 `0x333D83B0`。
