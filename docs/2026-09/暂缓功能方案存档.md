# 暂缓功能方案存档（2026-09-28 评审结论）

> 本文档记录「够用与否」评审后**决定暂缓**的功能方案。每项含：现状能力、完整方案留档、触发条件。
> 满足触发条件时按本文直接开工，无需重新调研。评审依据：`①不影响使用→仅记录 ②影响→最小方案修到能用`。

## 1. OCR 结构化 JSON 输出（OcrJson）——暂缓

### 现状能力（已够用）

| 需求 | 现有接口 | 说明 |
|---|---|---|
| 免字库识别 + 逐块坐标 + 置信度 | `AutoOcrEx(x1,y1,x2,y2,color,sim)` | 返回 `x1,y1,x2,y2,conf,text|...` 六字段管道串（**客户区坐标**，2026-09-29 真机验证修正） |
| 字库路径按词定位 | `FindStr` / `FindStrEx` | 返回命中词左上角坐标 |
| 字库路径逐块坐标 | **无**（唯一缺口） | `OcrEx` 只吐 `x,y,text`；但内部 `bin_ocr` 已算出 bbox+confidence（`ImageSearchAlgorithms.cpp:1872-1876`），只是输出格式丢弃 |

数据层 `ocr_rec_t`（`base/Types.h:140`）本来就有 `left_top/right_bottom/text/confidence` 四件套，**数据一直都有**。

### 方案留档（触发后照做）

- **接口**：`OcrJson(x1,y1,x2,y2,color,sim,retjson)` —— 截屏区域 → 自动选引擎（字库优先、免字库兜底，复用 `autoocr_ex` 判定逻辑，`ImageSearchService.cpp:882`）→ 统一返回：
  ```json
  {"ok":1,"code":0,"results":[{"text":"金币","bbox":[100,200,140,216],"confidence":0.93}]}
  ```
- **先例**：`YoloDetect` 的 `build_yolo_json`（`libop/op/OpYolo.cpp:20`）+ `base/JsonUtils.h`（EscapeString/FormatDouble），照抄即可
- **链路**：按 `op-new-api-flow` 七层（libop.h → OpOcr.cpp → op_c_api → op.idl 尾部 → OpAutomation → Python ctypes → tests）+ GuiSmoke + OPTool OCR 页「JSON 输出」区
- **批量多区域**：二期再做（签名复杂化，一期单区域够用）

### 触发条件（满足任一）

1. 字库 OCR 需要**逐字/逐词坐标**做点击定位（FindStr 的词级定位不够细）
2. Python 之外的语言（C#/易语言）要消费 OCR 结果，管道串解析成本高于 JSON
3. 需要「一次调用返回区域内全部文字+坐标」的结构化场景（如自动答读屏）

## 2. 截图后端选型——文档化即可，代码已齐全

### 后端调度现状（`binding/BindingSession.cpp:719` `createDisplay`）

| display 常量 | 值 | 后端 | 适用场景 | 备注 |
|---|---|---|---|---|
| `RDT_NORMAL` | NORMAL,0 | GdiCapture | 前台/普通窗口前台截图 | BitBlt 系；最小化后可后台截 |
| `RDT_NORMAL_DXGI` | NORMAL,1 | DxgiCapture | 桌面复制，BitBlt 黑屏的兜底 | 截的是屏幕区域，窗口不可遮挡 |
| `RDT_NORMAL_WGC` | NORMAL,2 | WgcCapture | Win10+ 窗口捕获 | **条件编译 `OP_ENABLE_WGC`**，当前构建需确认是否开启 |
| `RDT_GDI` / `RDT_GDI2` / `RDT_GDI_DX2` | GDI,* | GdiCapture | 后台 PrintWindow/BitBlt 窗口 DC | gdi/gdi2/dx2 已改 `PW_RENDERFULLCONTENT` + 全黑回退（2026-09-19，修 UWP/Chromium 全黑） |
| `RDT_DX_DEFAULT` / `RDT_DX_D3D9/10/11/12` | DX,* | HookCapture | DirectX 游戏后台帧（注入） | 需要 dx 渲染类型匹配；独占全屏最稳 |
| `RDT_GL_DEFAULT` / `RDT_GL_STD/NOX/ES/FI` | OPENGL,* | HookCapture | OpenGL 游戏后台帧（注入） | NOX=夜神模拟器专用 |

### 结论

- **不缺代码**，缺的是「哪个游戏绑哪个 mode」的经验表——上表即为选型表，遇到新游戏按渲染类型（DX9-12 / GL / 普通 GDI）对照选择
- 诊断小接口 `GetCaptureInfo`（返回当前后端名/帧信息）未做——截图出问题时先查 `GetFPS`/`GetFrameInfo`（已有）也可定位

### 触发条件（满足任一）

1. 目标游戏截图**黑屏/截到旧帧/全同帧** → 按上表换 mode 真机验证（DX11 窗口优先试 `RDT_NORMAL_DXGI`，游戏后台帧用 DX 系列）
2. 频繁遇到「绑定了不知道走的哪条截图链路」排查耗时 → 开工 `GetCaptureInfo`
3. WGC 后端需要进正式构建 → 确认 `OP_ENABLE_WGC` 构建开关 + 真机回归
