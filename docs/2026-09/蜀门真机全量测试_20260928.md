## 4. 首轮 9 FAIL + 2 EXC 的定性（`report_diag2.md`）

**全部为用法/判定问题，无一条是真缺陷。** 每条都补了反向验证，证明返回值有判别力。

### 4.1 签名类（2 EXC + 2 FAIL）—— 我传错类型

| 调用 | 真相 |
|---|---|
| `set_mouse_delay(20)` | 签名是 `(delay_type: str枚举, delay)` → `set_mouse_delay("normal", 20)` = True |
| `set_mouse_trajectory(1)` | 6 参 `(mode, min, max, jitter, start, end)` → `(0,0,0,18,0,0)` = True（默认值取自源码 `WinMouse` 构造） |
| `set_keypad_delay(10, 20)` | 同上 → `("normal", 20)` = True |
| 非法 type | `set_mouse_delay("bogus",20)` / `set_keypad_delay("bogus",20)` → **False**（反向验证通过） |

### 4.2 判定口径类（6 FAIL）—— 返回值本身是合法值

| 调用 | 真相 | 反向验证 |
|---|---|---|
| `get_window(PARENT=0)` → 0 | `= ::GetParent(hwnd)`；蜀门是无父/无主的顶层窗口 → **0 是正确值** | Win32 `GetParent` 同为 0；`TOP=7` 返自身 |
| `get_window(CHILD=1)` → 0 | `= ::GetWindow(hwnd, GW_CHILD)`；该窗口**子窗口数 = 0** | 拿一个真的**有 20 个子窗口**的窗口对照 → op 与 Win32 都返同一个首子窗口（65770） |
| `find_str_ex` → `''` | `''` = 未命中，与 `find_str` 的 `(-1,-1,-1)` 同一语义（源码 `out_str.clear()` 开头） | 装入真字库后 `find_str_ex` 返 `'0,28,31\|...'` |
| `fetch_words` → `''` | 源码要求 `rects.size() == words.size()`；我传 3 字符对 10 个块 → 必须空 | 字符数匹配后返 4 条字形 |
| `save_dict(0)` → False | dict 0 为空 → `ActiveDict` 返回空 → 正确失败 | 走完正向闭环后 = True，落盘 196 字节 |
| `autoocr_line`（全窗口）→ `''` | 单行快模式要求区域内**只有一行**；全窗口是误用，文档明写"语义由调用方承担" | 用 `autoocr_ex` 的 bbox 取单行区域 → 返 `'池'` |

### 4.3 `move_r` 相对位移偏差 —— 系统指针加速，非 op 缺陷

实测倍率（注册表 `MouseSpeed=1, MouseThreshold1=6, MouseThreshold2=10, MouseSensitivity=10`）：

| 请求 dx | 实际 dx | 倍率 |
|---|---|---|
| +10 | +16 | 1.60 |
| +20 | +42 | 2.10 |
| +50 | +170 | 3.40 |
| +100 | +372 | 3.72 |
| +200 | +774 | 3.87 |

倍率**随幅度非线性上升** = Windows 指针加速曲线。op 的 `MoveR` 在 `IN_NORMAL` 模式下走
`SendInput(MOUSEEVENTF_MOVE)`（**相对**鼠标单位），必然经过 OS 加速/灵敏度换算；而 `MoveTo` 走
`MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK`，实测像素级精确。

> **结论（要写进使用约定）**：要精确落点用 `move_to`；`move_r` 只能当"大致挪一下"，不能做像素断言。

### 4.4 新增语义发现（非缺陷，但容易踩）

| 项 | 事实 | 影响 |
|---|---|---|
| **`add_dict` 只吃单条字形** | `detect_text_entry_format` 按 `$` 切分：3 段 = op 单条、4 段 = 大漠单条，其余 = unknown → False。而 `fetch_words` 输出是**多行**（每行一条） | 多行产物直接喂 `add_dict` **必然 False**；要逐行加，或走文件（`set_dict` 内部逐行解析）。建议文档补一句 |
| **`set_ocr_engine` 忽略 engine/dll 参数** | 源码 `OnnxOcrEngine::init` 内 `(void)engine; (void)dllName;` —— 内置 ONNX 引擎不读这两个参数 | 传不存在路径**仍返 True**（因为它加载的是内置模型）。唯一拒绝路径 = `http*`/`tesseract`/`paddle` 别名（HTTP 后端未编译）→ 返 False |
| **本地字库优先级高于 AI 引擎** | `FindStr/FindStrEx/AutoOcr*` 都是 `if (!dict) → AI 引擎 else → 本地字库` | 字库 0 里残留字符会让后续测试**整体换口径**（本轮就出现过：D 段装完字库后 E 段全返 `'xxxx'`）。测 AI 路径前必须 `clear_dict(0)` |
| **`write_int(0x400000)` 恒 False** | 0x400000 是 PE 只读镜像页（同址 `read_int` = 0x905A4D = "MZ" 正常） | 跨位数写**不是不支持**；靶点必须选可写页 |
