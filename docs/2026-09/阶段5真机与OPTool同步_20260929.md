## 二、两次"我以为产品有问题，其实是我调用错了"

按既定判据：**先怀疑输入，再怀疑实现**。两次都验证了这一点。

### 1. `cv_match_template` 返回 `{"ok":0}` 而 rot 版本 `ok:1`

排查（`op_cv_probe.py`）跑了 method × color_mode 全组合：

| method | color_mode | 结果 |
|---|---|---|
| 1 SQDIFF_NORMED（默认） | 1 GRAY（默认） | **HIT** score=0.866 |
| 1 SQDIFF_NORMED | 0 COLOR | HIT |
| 5 CCOEFF_NORMED | 0 / 1 | HIT（灰度下 score=1.0） |
| **0 SQDIFF（未归一化）** | **1 GRAY** | **MISS** |
| 0 SQDIFF（未归一化） | 0 COLOR | HIT |

结论：**未归一化的 `SQDIFF/CCORR/CCOEFF` 原始分值不落在 0~1，`threshold` 对它没有意义**。
我原先传了 `method=0`，才出现"rot 成功、非 rot 失败"的假象（两者 method 相同、color_mode 不同）。

> **已知不一致（不改）**：rot 路径会把未归一化分值也映射成 0~1（所以 `method=0` 时它 HIT），
> 非 rot 不做映射（MISS）。默认 `method=SQDIFF_NORMED` 不受影响；按"够用为主"记为文档项，
> 改动会波及 OpenCV 的 30 条既有用例，收益 < 风险。判据：**用 `*_NORMED`**。

### 2. `set_window_state(7)` 不解除最小化

我原以为 7 能把最小化窗口恢复 —— 实测不能。查 `WindowState.cpp:194`：

```
flag=7  -> ShowWindow(SW_SHOW) + SetForegroundWindow   // "显示指定窗口"
flag=12 -> ShowWindow(SW_RESTORE)                      // "恢复并激活指定窗口"
flag=5  -> ShowWindow(SW_SHOWNOACTIVATE)               // "恢复指定窗口，但不激活"
```

**这是大漠语义，不是缺陷**：`SW_SHOW` 不解除最小化，解除要用 `SW_RESTORE`（flag 12）。
测试脚本已按正确口径重写，并**反向钉住**「7 之后仍应保持最小化」，防止后人"顺手改成 RESTORE"破坏兼容。
