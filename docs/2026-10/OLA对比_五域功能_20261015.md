# OLA vs op 五域功能对比：OCR / 窗口 / 后台键鼠 / YOLO / 图色（2026-10-15）

> 对照基准：op 公开 API 255 个（`include/libop.h` 提取）vs OLA 文档站五模块
> 接口页 229 个（文字识别 51 / 窗口 59 / 鼠标 33+键盘 11+键鼠同步 8 / YOLO 34 /
> 图像处理 113+图像识别 32，见 `OLA文档站功能全量清单_20261015.md`）。
> 判定口径：**建议新增**（有真实使用场景、与 op 定位契合、工作量可控）/
> **低优先**（有场景但窄）/**不建议**（与 op 开源定位不符或已有等价能力）。

## 一、OCR（OLA 51 vs op 字库系+免字库系）

op 已覆盖：区域/文件识别、字库管理（SetDict/AddDict/SaveDict/GetDict/SetMemDict）、
免字库 AutoOcr 门面（含颜色分路/单行快模式/结构化输出）、FindStr 全部结果。

| OLA 有 op 无 | 判定 | 理由 |
|---|---|---|
| OcrDetails / OcrDetailsEx（逐字置信度+坐标） | **建议新增** | op 结构化输出只有 AutoOcrColorEx（词级）；字库系与免字库系都缺逐字 Details，排障/校准常用 |
| OcrWarmupModel / OcrWarmupModels（模型预热） | **建议新增** | 消除首次识别卡顿（模型加载+lazy 初始化都压到第一次调用），游戏自动化开场就要读数，预热接口工作量小 |
| 模型加密包生态（OcrEncryptModel/Decrypt/加密包类型检测） | 不建议 | 模型保护是商用闭源诉求，op 模型本来开源分发 |
| OcrListModels / OcrActivateModel / OcrGetModelInfo（多模型管理） | 低优先 | op 单例单引擎够用；多模型并发生态复杂度高 |
| OcrFromBmpData（字节流直识别） | **建议新增** | op 已有 GetScreenDataBmp 返回字节流，只缺「字节流→识别」入口，顺手 |
| FastNumberOcr（专用快速数字） | 低优先 | op OcrAutoColorLine 单行快模式已覆盖大部分场景 |
| 字库 txt 互操作（ImportTxtDict/ExportTxtDict/InitDictFromTxt） | **建议新增** | 字库与外部 txt 互导是真实工作流（多人协作制库、跨工具迁移），工作量小 |
| ImportDictWord / RemoveDictWord（词条级增删） | 低优先 | op AddDict 单条添加已有；删除词条可补但场景窄 |
| GetDictImage（读字库图片） | 低优先 | 制库调试辅助 |
| OcrSetModelConfigByKey（运行期改推理配置） | 不建议 | op init 时 argv 已覆盖，运行期热改配置易引入不一致 |

## 二、窗口（OLA 59 vs op）

op 已覆盖：绑定/解绑/查绑定、枚举/查找（含按进程）、矩形/客户区/标题/类名、
SetWindowText/Size/State/Transparent、MoveWindow、剪贴板、SendString(IME)/SendPaste、
DisableMinMax、LockWindowPosition/Size、LockInput、DownCpu、LayoutWindows（op 独有）。

| OLA 有 op 无 | 判定 | 理由 |
|---|---|---|
| GetWindowDpiAwarenessScale / GetScaleFromWindows（窗口级缩放比） | **建议新增** | op 内部做 DPI 换算但对外查不到比例；多缩放比环境排障刚需，几行代码 |
| GetWindowThreadId | **建议新增** | 与 GetWindowProcessId 对称，trivial |
| EnumWindowSuper / FindWindowSuper（超级枚举/查找） | 低优先 | 具体过滤维度未核实；op EnumWindow 带 filter，可能已等价，需看 OLA 参数细节再定 |
| SendPaste2 / SendPaste3（CtrlV 变体） | 不建议 | op SendPaste 已覆盖语义，变体是兼容历史 |
| SendString2 / SendStringIme2 | 不建议 | 同上 |
| GetProcessIconImage（进程图标提取） | 低优先 | 场景窄（任务栏类工具） |
| ReleaseWindowsDll（强制卸载注入 DLL） | 低优先 | 解绑清理的兜底，op 绑定有自己的释放路径 |

## 三、后台键鼠（OLA 鼠标 33 + 键盘 11 + 键鼠同步 8 vs op）

op 已覆盖：三键点击/按下/弹起/双击、滚轮/HWheel、MoveTo/MoveR/MoveToEx(+Smooth)、
MovePath/DragPath（拟人轨迹）、GetCursorPos/GetCursorShape、WaitKey、
KeyDown/Up/Press(+Char)、KeyPressStr、SetMouse/KeypadDelay、SetIme、绑定模式 display/mouse/keypad。

| OLA 有 op 无 | 判定 | 理由 |
|---|---|---|
| 键鼠同步系（InputRecord/InputPlayback/InputSyncLink 录制回放多开同步，8 接口） | 低优先 | 场景真实（多开同步器）但是大功能，且与自动化主链正交；留作中期候选 |
| SetMousePosCallback（全局鼠标位置回调监听） | **建议新增** | 防检测/人机校验联动/操作审计都用得上，与现有 hook 基建同向 |
| GenerateMouseTrajectory / GenerateInvoluteMouseTrajectory（轨迹生成） | 低优先 | op 拟人轨迹已内置执行（MovePath/MoveToSmooth）；「生成不执行」场景窄 |
| GetCursorImage（鼠标图标图像，op 只有 Shape 特征码） | 低优先 | Shape 特征码已能判形态；要图像本身场景窄 |
| KeyPressHotkey（显式组合键发送） | **建议新增** | 已核实 op 只解析单键（vkmap 名或单字符），不支持 "ctrl+alt+a" 多键串；key_combo_t 基建现成，解析加号串即可 |
| MoveToWithoutSimulator（SetCursorPos 直移） | 不建议 | op MoveTo 的 normal 模式即等价 |
| PackPoint/UnpackPoint(X/Y)（坐标打包成 int64） | 不建议 | 语言层便利函数，COM 已能直接传两参 |
| EnableMouseAccuracy / SetWindowCursor（系统精度/光标矫正） | 不建议 | 改全局鼠标精度副作用大，自动化插件不该碰 |

## 四、YOLO（OLA 34 vs op 3：SetYoloEngine/YoloDetect/YoloDetectFromFile）

op 已覆盖：检测（屏幕区域/文件）、多格式模型（内置资源/外挂 .onnx 统一入口）、
v5/v8/v11 自适应解码、类别感知 NMS、类别名三元来源。

| OLA 有 op 无 | 判定 | 理由 |
|---|---|---|
| 四类扩展任务：Classify/Pose/Segment/Obb（分类/姿态/分割/旋转框）× 3 源 | **建议新增** | 同一个 ONNX 解码框架扩展输出头即可，OLA 已验证需求存在；游戏自动化里姿态/旋转框（斜置血条/物品框）是真场景 |
| YoloListDevices（推理设备枚举选择，GPU） | **建议新增** | ORT 支持 CUDA/DirectML，op 目前跑 CPU；设备选择是免费的性能项 |
| YoloListModels / YoloReleaseModel / YoloGetModelInfo（多模型管理） | 低优先 | 单模型够用；多模型切换场景有但不广 |
| YoloSetModelConfig(ByKey)/GetModelConfig（运行期推理配置） | 低优先 | init argv 已覆盖主流配置 |
| 模型加密包生态 | 不建议 | 同 OCR，商用保护诉求 |

## 五、图色（OLA 图像处理 113 + 图像识别 32 vs op 图色系 + OpOpenCv 40 接口）

op 已覆盖：找图（FindPic 系/大漠语义/多模板 CvMatch 8 变体含旋转/缩放/特征/边缘/形状）、
找色找块（FindColor/Block/MultiColor 各 Ex 变体）、字库点阵 OCR、取色/颜色数量、
屏幕数据（GetScreenData/Bmp/FrameInfo/FPS）、图片缓存、OpenCv 文件级处理
（阈值/形态学基本四件/模糊/锐化/轮廓/连通域/流水线）。

| OLA 有 op 无 | 判定 | 理由 |
|---|---|---|
| 图片比较四件套：MSE / IsSameImage / 直方图 / SSIM | **建议新增** | 场景硬：过场判定、截图比对回归、找图结果校验；纯算法无基建依赖，放 opcv 最合适 |
| IsDisplayDead / GetWindowsFps（卡屏/掉帧检测） | **建议新增** | 游戏自动化稳定性刚需（画面卡住时一切找图都在空转），op 有 FrameInfo 基建，实现近 |
| MatchAnimation（动画窗口匹配，多帧） | **建议新增** | 静态模板对动态 UI 失效是常见痛点；可用「连续 N 帧各做一次模板匹配聚类」低成本实现 |
| DecodeQRCode / CreateQRCode（二维码） | 低优先 | 场景有（扫码登录/支付）但引入解码库依赖，可与图像处理增强打包评估 |
| 形态学补全：Gradient / Tophat / Blackhat | **建议新增** | op CvMorphology 已有 open/close/erode/dilate，补三个枚举值即可，trivial |
| Skeletonize 骨架化 | 低优先 | op CvThin（Zhang-Suen/Guo-Hall）基本等价，命名差异 |
| RGB2HSV / Hex 颜色互转等颜色空间转换 | 低优先 | op 内部 HSV 比较已有，公开转换接口顺手但场景窄 |
| ImageStitch 拼接系 / ConcatImage / CoverImage | 低优先 | 截图拼接汇报类场景，窄 |
| ShowImage 弹窗显示 | 低优先 | 调试辅助，顺手可做 |
| GetForegroundPoints（前景点提取） | 不建议 | op 二值化+内部 get_rois 已覆盖语义 |
| BitPacking/Unpacking（二值图压缩串） | 不建议 | 字库传输场景已被 op 字库文件/内存字库覆盖 |
| SetPixel/DrawRectangle/DrawCircle（图像内绘制） | 低优先 | 标注/调试图层场景，屏幕绘制层做了更实用 |
| RemoveImageDiff / RemoveOtherColors / RemoveIslands | 不建议 | 太专用，二值化参数可调出等价效果 |

## 汇总：建议新增清单（按价值/工作量排序）

| # | 功能 | 域 | 工作量 | 说明 |
|---|---|---|---|---|
| 1 | YOLO 扩展任务（分类/姿态/分割/旋转框） | YOLO | 中 | 解码头扩展，框架现成 |
| 2 | 图片比较四件套（MSE/SSIM/直方图/同图判定） | 图色 | 小 | 纯算法，进 opcv |
| 3 | OCR 模型预热（Warmup） | OCR | 小 | 消除首识卡顿 |
| 4 | 卡屏/掉帧检测（IsDisplayDead/FPS） | 图色 | 小-中 | FrameInfo 基建现成 |
| 5 | OCR Details（逐字置信度+坐标） | OCR | 小-中 | 两系 OCR 各补一个输出格式 |
| 6 | 窗口级 DPI 缩放比 + GetWindowThreadId | 窗口 | 小 | trivial 两件套 |
| 7 | 字节流直识别（BmpData→OCR，与 YOLO 对齐） | OCR | 小 | GetScreenDataBmp 已返回字节流 |
| 8 | 显式组合键发送（KeyPressHotkey，"ctrl+alt+a" 语法） | 后台 | 小 | key_combo_t 基建现成，补加号串解析 |
| 9 | 鼠标位置全局回调（SetMousePosCallback） | 后台 | 中 | 与 hook 基建同向 |
| 10 | 动画匹配（MatchAnimation） | 图色 | 中 | N 帧聚类方案 |
| 11 | 形态学补三枚举（Gradient/Tophat/Blackhat） | 图色 | 小 | 加枚举值 |
| 12 | 字库 txt 互导（Import/ExportTxtDict） | OCR | 小 | 字库工作流 |
| 13 | YOLO 推理设备选择（GPU） | YOLO | 小-中 | ORT provider 配置 |

中期候选（单独立项再议）：键鼠同步录制回放、YOLO/OCR 多模型管理、屏幕绘制 GUI 层、
二维码（带依赖评估）。

**已核实为覆盖误判的**：LockInput/DownCpu/WaitKey/DisableMinMax/LockWindowPosition/
GetCursorShape/SendPaste/SendStringIme——OLA 有 op 也有，不在新增范围。
