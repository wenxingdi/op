整体评价：小模块（1382 行），且是全场注释质量最好的区域——每一处历史 bug 修复
（replace 下溢、split、KMP 命中条件、Delay 忙等、rand 线程级种子、point_t 非严格弱序）
都有「旧实现错在哪」的归因注释。**未发现真 bug，效率问题也没有**（Delay 已改
MsgWait 阻塞、随机已 thread_local 化）。问题只有几处双份实现和一处输出小瑕疵。

## B1【精简·低】split / string2upper / string2lower 宽窄双份可模板化

**位置**：`Utils.cpp` L163-209。`split`、`string2upper/lower` 与 `wstring2upper/lower`
六函数，宽窄两版算法逐行相同，仅字符类型不同（`replace` 已示范了内部模板
`replace_impl` 的正确姿势）。
**方案**：照 `replace_impl` 模式提 `split_impl` / `case_impl`，六个公开函数缩为一行
转发。**注意保持 `split` 的尾空段丢弃语义**（`split("a|") → ["a"]`，多个调用方
可能依赖，勿顺手"修正"）。预计 -40 行。

## B2【精简·微】PTY/PTX 与 GET_RENDER_TYPE/GET_RENDER_FLAG 两套相同 helper

**位置**：`Utils.h` L48-54（`constexpr PTY/PTX`）vs `AutomationModes.h` L52-54
（宏 `GET_RENDER_TYPE/FLAG`）——同一「高 16 位 type / 低 16 位 flag」拆包的两套实现。
**实证**：image 系 7 处用 PTY/PTX，binding/capture 系 5 处用 GET_RENDER_*，互不交叉。
**方案**：统一到一套（建议保留 AutomationModes.h 里与 MAKE_RENDER 同处的宏，删
Utils.h 的 PTY/PTX，改 image 系 7 处调用）。纯改名，零行为变化。预计 -6 行 + 7 处改名。

## B3【精简·微】setlog 输出双换行

**位置**：`Utils.cpp` setlog_text——`stringstream` 内已 `<< std::endl`，三个分发分支
又各自 `<< std::endl` 一次，日志文件/stdout 每条记录之间多空一行。
**方案**：删掉 setlog_text 里 stringstream 的 `std::endl`（输出处保留唯一换行）。
纯排版修正，但日志是排障主渠道，顺手修。

## B4【观察项】GetLastErrorAsString 失败路径未防御

**位置**：`Utils.cpp` L249-272。`FormatMessageA` 失败（返回 0）时 `messageBuffer`
为 nullptr，直接 `std::string(messageBuffer, size)`——MSVC 下 `size=0` 不崩但不合标准。
**结论**：实际从未出问题（FormatMessage 对系统错误码几乎不失败），加一行
`if (size == 0 || messageBuffer == nullptr) return "";` 更稳。可与 B3 合并为一笔微修，
不单独立项。

## 观察项（记录不动）

- **utf8_to_ansi 硬编码 CP936**（`Utils.cpp` L57-77）：非中文系统上是错的，但 op
  目标市场就是中文环境（大漠生态），改 CP_ACP 反而与旧行为不兼容。记录不动。
- **ThreadPool 并非死码**：`TemplateMatcher.cpp` L56 的 OpenCv 线程池在用
  （hardware_concurrency 个 worker）。保留。
- **Types.h `byte` 与 `uchar` 双别名**（L14/L152）：历史遗留，各自有引用，合并改名
  触碰面广收益零。不动。
- **hex2bin/bin2hex 内联于头**（`Utils.h` L32-46）：`bin2hex` 把两个字符打包进
  int（宽字符语义），形状古怪但 ProcessMemory 等调用方钉住了行为。不动。
- **AutomationModes 共享内存/互斥体名值颠倒**（L91-98）：历史契约，宿主与注入 DLL
  两侧一致即正确，注释已冻结。不动。
- **rect_t::shrinkRect 的 `-=w; +=1` 写法**（Types.h L85-91）：等价于 `x2 = x2-w+1`，
  语义被找图调用方依赖。不动。

## 其余结论（无实质问题）

- **JsonUtils.h 176 行零问题**：EscapeString 控制字符 `\u00XX` 处理、UnescapeString
  代理对拼码点、明确声明「不做完整 JSON 语法解析」，注释完整。
- **Delay 系已是最优形态**：MsgWaitForMultipleObjectsEx 阻塞 + 消息泵派发 + WM_QUIT
  不吞，注释含旧忙等实现的 CPU 代价分析。
- **随机系线程安全已闭环**：SeedProcessRandom（进程级一次性）+ thread_local
  mt19937（rand_range/rand_unit_signed），MSVC rand() 线程级种子的坑有完整注释。
- **Environment 完整性级别判定**：UIPI「假成功」前置拦截的误伤/放行取舍有注释。
