# 后台绑定模块分析（2026-10-15）

> 逐模块精简/效率专项 · 第 1 模块。范围：`libop/binding/`、`libop/capture/`（含 4 个后端）。
> 方法：通读 BindingSession（814 行）、ICaptureBackend（114 行）、GdiCapture（436 行）、
> DxgiCapture（421 行）、HookCapture（467 行）， skim WgcCapture（1317 行）。

## 结构总览

```
Op::BindWindowEx (OpInput.cpp 门面)
  └─ BindingSession::BindWindowEx          模式串解析 / UIPI 预检 / 候选回退编排
       ├─ createDisplay → GdiCapture | DxgiCapture | WgcCapture | HookCapture
       ├─ createMouse / createKeypad       Win* 前台 / Dx* 注入（input/ 模块）
       └─ input_hook_client::PingHook      dx 注入活性回环
截图链路：OpCaptureHelpers → BindingSession::requestCapture
       ├─ screen → ICaptureBackend::requestCapture（各后端）
       └─ pic/mem → _pic 逐行 memcpy（SetDisplay 设置）
```

绑定主流程整体健康：失败原因码（10-14 批次）、UIPI 预检、钩子活性回环、
auto 候选回退等近年加固都在位。问题集中在**注释死代码、双份维护、
回退循环冗余重建、两处 per-frame/绑定期效率**。

## 预期收益

- 代码：净减约 120~150 行（死代码 + 重复合并），15 项模式映射单源化；
- 效率：auto 回退从"每候选一轮键鼠跨进程绑定"降为 1 轮；SetDisplay(pic:) 省一次全图深拷贝（Image 移动语义）；
- 健壮性：BindEx 补齐与 UnBindEx 对等的异常护栏。

  stash 回退后重编）在相同 WgcTest-only 跑法下级联复现，日志同为

  防护锁存（`WGC broken by previous in-process SEH fault ... bind skipped`）→ 后续全部 fast-fail。
  此前 13:21 全量跑 10/10 过，说明该 flake 与"WGC 是否进程内首个使用"的时序相关，非代码回归。

## 补记：输入后端绑定交叉核对（2026-10-15 第 3 弹键鼠输入模块分析时回填）

第 3 弹通读 `libop/input/` 后，对本文档 B3（auto 回退只重建 capture）的前置假设做完整核验，
并补充输入后端绑定的现状记录：

- **B3 前提成立**：`WinMouse::Bind`/`WinKeyboard::Bind` 均为纯状态赋值（无窗口交互、无消息），
  循环外绑定一次安全；`DxMouse`/`DxKeyboard::Bind` 才有跨进程注入（带 `_hwnd==h && _mode==mode`
  同参数短路，重复绑定零开销）。
- **输入后端绑定的异同**（备查）：
  | 后端 | Bind 校验 | 重复绑定 | UnBind 副作用 |
  |---|---|---|---|
  | WinMouse | 无 hwnd 校验（D2 已立案） | 无短路 | 纯清状态 |
  | WinKeyboard | `IsWindow` 校验 | 无短路 | 清修饰键状态 |
  | DxMouse/DxKeyboard | 注入失败返回错误码 | 同参短路直接返回 1 | 远端钩子解绑 |
- **dx 通道拟人化轨迹**：DxMouse 不覆写 MoveToSmooth/MovePath/DragPath/SetMouseTrajectory，
  经多态复用 WinMouse 实现，轨迹每个点走 `DxMouse::MoveTo`（OP_WM_MOUSEMOVE 逐点发到目标窗口）。
  即"绑定 dx + 平滑移动"组合在代码层是通的（10-14 文档 H3 的代码层答案），真机效果仍属真机项。
- 详细问题清单见 `键鼠输入模块分析_20261015.md`（D1-D5）。
