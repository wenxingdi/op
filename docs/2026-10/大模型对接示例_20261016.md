# OP 对接大模型 API 示例（2026-10-16）

> 依赖：第二十七批 JSON 族（OpJson*）+ 第二十八批 HTTP 小族（OpHttp*）。
> 闭环：**OpJsonSetString 拼请求体 → OpHttpPost 发送 → OpJsonGetString/OpJsonGetNumber 取结果**。
> 不依赖任何外部库，脚本宿主无 JSON/HTTP 能力也能用。
> 本文所有 key 均为占位符，真实密钥不要硬编码进分发的脚本。

## 通用调用流程

```
1. body    = 请求体 JSON 文本：宿主自己有 JSON 库就直接拼；
   没有则用 OpJson* 族拼（OpJsonSetString 建 model，OpJsonAppend 逐条加 messages 元素）
2. headers = OpJsonSetString("", "", ...) 逐步写入
             {"Authorization":"Bearer <key>","Content-Type":"application/json"}
3. resp    = OpHttpPost(base_url, body, headers, 30000)
4. reply   = OpJsonGetString(resp, "choices.0.message.content")
5. tokens  = OpJsonGetNumber(resp, "usage.total_tokens")     ← 数值型字段用 GetNumber
6. error   = 若 reply 为空，查 OpJsonGetString(resp, "error.message")
```

**两个必知约定**（详见 API 手册 HTTP/JSON 分区）：

- c_api 字符串返回共用 `string_result` 缓冲：**每次取到字符串先拷贝成自己的变量，再调下一个字符串函数**，否则上一次结果被覆盖。
- `OpHttpPost` 非 2xx 也返回响应体（错误 JSON 可见），传输失败才返回空串——判错用第 6 步，不要用"返回空"判错。

## 平台参数（2026-10-16 实测连通）

| 平台 | base_url（OpHttpPost 的 url 参数） | 模型（实测可用的写法） |
|------|-----------------------------------|------------------------|
| agnes | `https://api.agnes-ai.cn/v1/chat/completions` | `agnes-2.5-flash`（`agnes-2.0-flash` 平台侧 503 无渠道，勿用） |
| DeepSeek | `https://api.deepseek.com/chat/completions` | `deepseek-flash`、`deepseek-v4-pro`（**必须小写**，大写 400） |
| 智谱 BigModel | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-4-flash`、`glm-4v-flash`、`GLM-4.1V-Thinking-Flash`（按此大小写） |

未通过实测的：SiliconCloud（账号需实名认证，403，与本插件无关）、`glm-4.7-flash`（平台临时限流 1305，非 key 问题）。

## 完整示例（python ctypes，可直接运行）

> python ctypes 的 `c_wchar_p` 返回值在调用返回时已拷贝为 Python str，
> 天然规避了共享缓冲陷阱；按键精灵/COM 侧（BSTR 也是拷贝语义）同样安全。
> 直接调 C API 的 C/C++ 用户需要自己 `wcscpy_s` 备份返回值。

```python
import ctypes, json

dll = ctypes.CDLL(r"op_c_api_x64.dll")            # 换成你的路径
dll.OpCreate.restype = ctypes.c_void_p
dll.OpDestroy.argtypes = [ctypes.c_void_p]
for n in ("OpHttpPost", "OpJsonGetString"):
    getattr(dll, n).restype = ctypes.c_wchar_p    # 字符串结果自动拷贝
dll.OpJsonGetNumber.restype = ctypes.c_int
dll.OpJsonGetNumber.argtypes = [ctypes.c_void_p, ctypes.c_wchar_p, ctypes.c_wchar_p,
                                ctypes.POINTER(ctypes.c_double)]

op = dll.OpCreate()
handle = ctypes.c_void_p(op)

def ask(base_url, key, model, content, max_tokens=200):
    # 1. 拼请求体（python json.dumps 出来的就是合法 JSON 文本，直接当 body）
    body = json.dumps({"model": model,
                       "messages": [{"role": "user", "content": content}],
                       "max_tokens": max_tokens})
    # 2. 拼请求头（headers_json 是 JSON 对象文本）
    headers = json.dumps({"Authorization": "Bearer " + key,
                          "Content-Type": "application/json"})
    # 3. 发送
    resp = dll.OpHttpPost(handle, base_url, body, headers, 30000)
    # 4. 取结果：正文 / 平台报错 / token 数
    reply = dll.OpJsonGetString(handle, resp, "choices.0.message.content")
    err = dll.OpJsonGetString(handle, resp, "error.message")
    tok = ctypes.c_double(0)
    dll.OpJsonGetNumber(handle, resp, "usage.total_tokens", ctypes.byref(tok))
    return reply, err, int(tok.value)

# agnes 示例（DeepSeek/智谱只换 url、key、model 三个参数）
print(ask("https://api.agnes-ai.cn/v1/chat/completions",
          "sk-<你的key>", "agnes-2.5-flash",
          "用一句话介绍你自己"))

dll.OpDestroy(handle)
```

## 各平台切换

只改 `ask()` 的三个参数：url、key、model。其余代码不动。
中文内容直接写进 content 即可——请求体按 UTF-8 发送、响应按 UTF-8 解码，已实测中文问答正常。

## 思维链模型的注意点

`GLM-4.1V-Thinking-Flash` 与 `deepseek-flash`（R1 系推理）会先输出推理过程：

- 智谱 GLM-4.1V-Thinking：推理内容直接混在 `choices.0.message.content` 里（`<think>...</think>` 标签），脚本侧按需剥离标签取正文。
- DeepSeek：推理在 `choices.0.message.reasoning_content` 字段，正文在 `content`，两者分开取。
- **max_tokens 要留大**（≥500）：思维链会消耗 completion_tokens，太小会被推理吃光导致正文截断（finish_reason=length）。

## 密钥安全

- key 不要硬编码进分发的脚本/文档；用配置文件或环境变量读入后用 `OpJsonSetString` 拼进 headers。
- key 泄漏（截图、日志、版本库）后立刻到平台后台轮换。
