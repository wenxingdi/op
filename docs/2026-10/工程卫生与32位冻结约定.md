# 工程卫生与 32 位冻结约定（2026-10-14）

> 依据：2026-10-14 全面分析（四维度盘点）后拍板执行。原则：**够用为主，不追求完美**。

## 一、32 位（x86）链路冻结

**决策**：保留 32 位代码与历史构建能力，但**不再投入**——新功能只验 x64，x86 不做优化、不补测试、不追回归。

**保留原因**（不是鸡肋，别删）：
- `op_x86.dll` / `op_c_api_x86.dll` 服务于 **跨位数 dx 注入**（64 位宿主注入 32 位目标进程）
- CMake 中有实质分支：x86 无官方 32 位 onnxruntime 包 → 内置 OCR/YOLO 编译期整体关闭（`libop/CMakeLists.txt:198/605`）
- x86 下 `__stdcall` 导出名带装饰 → 需从 `op_c_api.h` 生成 `.def` 裸名导出（`libop/CMakeLists.txt:476-499`）

**冻结边界**：
| 项 | 状态 |
|---|---|
| `scripts/build/_wb_build_*_x86.py`、`_wb_build_blackbone_x86.py` | 冻结（不维护，能用就用） |
| `bindings/python/op/bin/x64/op_*_x86.dll` | 冻结（历史产物，随发布件同步） |
| x86 相关测试/真机验证 | 不做 |
| 新 API（如 `GetDisplayMethod`） | 只验 x64；idl 与绑定层天然跨位，无需额外适配 |

需要 x86 二进制时，从备份 tag（`v2026.09.28-predev` 等）或 `scripts/backup/` 的发布件取。
