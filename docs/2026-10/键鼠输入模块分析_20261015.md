> 分析方法同前两弹：先出清单 → 用户确认 → 再实施。

## 结构总览

```
门面 OpInput.cpp → bkproc._mouse / _keypad（ICaptureBackend 同款后端切换）
  ├─ WinMouse / WinKeyboard：前台通道
  │    ├─ IN_NORMAL   SendInput 键鼠事件
  │    ├─ IN_NORMAL2  键盘扫描码模式（扩展键标志补齐，含错误日志）
  │    └─ IN_WINDOWS  Post/SendMessageTimeout 窗口消息（lParam 扫描码/扩展键/alt 语义齐）
  └─ DxMouse / DxKeyboard：注入通道（继承 Win*，覆写为 OP_WM_* 钩子消息）
         平滑移动/路径/轨迹参数不覆写 → 多态复用 WinMouse 实现，MoveTo 逐点走 dx 消息
```

延时常量在 AutomationModes.h（MOUSE_NORMAL_DELAY 等 6 个，extern long 可调）。
随机源：`Utils` 的 thread_local mt19937（`rand_range` / `rand_unit_signed` /
`jittered_delay_ms` / `DelayJitter` ±40%）。

## 补记：拟人化轨迹增量评估（2026-10-15 用户问询，判定不做）

**结论：必要性不大，记为触发条件式观察项，本轮不动。**

- 现状已覆盖初级统计特征检测（直线/定速/定步长/精确落点/恒定节奏全有随机化）；
  剩余缺口是对称速度曲线与无过冲修正——属第二特征，只有专门做运动学分析的行为检测才用，
  而目标场景的主要矛盾在输入来源检测（SendInput 标志）与聚合行为特征（频率/作息），轨迹形状不是主要战场。
- 项目方法论不支持无观测缺口先补复杂度（H1 教训：能力无判别力验证=可能是坏的）。
- 处置：真机遇到行为检测封号/验证挑战且能归因到轨迹特征时再启动，前置步骤是
  先在 workbench 跑轨迹相似度/长度分布基准探针（E-A 批 A/B 反向验证思路）。
- 唯一例外候选：非对称 ease 速度曲线（~5 行、零风险、改善匀速感），下批可作为微项顺手带。
