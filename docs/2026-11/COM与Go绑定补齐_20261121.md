## 二、COM `SetAStarMapData`（DISPID 478）

### 2.1 做法

照 `SetMemDict` 的先例走：字节流用 `SAFEARRAY(BYTE)`（易语言侧就是字节数组），
`size` 由数组上界推出，不额外传。

```idl
[id(478)] HRESULT SetAStarMapData([in] LONG width, [in] LONG height, [in] SAFEARRAY(BYTE) data,
                                  [in] LONG scale, [in] LONG offset_x, [in] LONG offset_y,
                                  [out, retval] LONG* ret);
```

三个文件：`op.idl`（加 id）、`OpAutomation.h`（声明）、`OpAutomation.cpp`（实现，含
`SafeArrayGetDim/GetVartype/LBound/UBound/AccessData` 全套校验，参数非法一律 `ret=0` 返回 `S_OK`）。

### 2.2 验证：免注册的 late-binding 探针

`scripts/probes/com_astarmapdata_probe.cpp` —— **不写注册表**（不 regsvr32）：

```
LoadLibrary(op_x64.dll)
  -> DllGetClassObject(CLSID_OpAutomation, IID_IClassFactory)
  -> CreateInstance(IID_IDispatch)
  -> GetIDsOfNames("SetAStarMapData")   // 实测 DISPID = 478
  -> Invoke(SAFEARRAY(BYTE) 32x32 中间 4x4 涂黑)
  -> 再用既有 IsLineBlocked 横穿障碍
```

实测输出：

```
[diag] SetAStarMapData -> DISPID 478
[diag] SetAStarMapData argc=7 -> hr=0x8002000E   (DISP_E_BADPARAMCOUNT)
[diag] SetAStarMapData argc=6 -> hr=0x00000000
ret=1
[diag] IsLineBlocked -> DISPID 373 ; argc=4 -> hr=0
IsLineBlocked(ret=1)     // 穿过黑块 = 被挡
RESULT: PASS
```

## 三、COM late-binding 两个必须记住的坑（本轮踩了两个）

### 3.1 `DISPPARAMS.rgvarg` 是**逆序**的

`rgvarg[0]` 是**最后一个**形参。这条错了的表现极阴：

- 全是 `VT_I4` 的方法（`IsLineBlocked`）**反不反转都能跑**，看起来完全正常；
- 一旦参数里混进 `SAFEARRAY`，就报 `DISP_E_TYPEMISMATCH`（0x80020005），
  错误信息完全不提"顺序"两个字。

本轮第一次跑就是 `TYPEMISMATCH`，改成逆序后立刻通过。

### 3.2 `[out, retval]` 用 `pVarResult` 回传，**不占形参**

`SetAStarMapData` 有 6 个 in 参数 + 1 个 `[out,retval]`，
但 `Invoke` 只能传 **6** 个 VARIANT；传 7 个报 `DISP_E_BADPARAMCOUNT`。
出参值从 `pVarResult`（`VARIANT*`）取，不是从 `VT_BYREF` 参数槽。

> 这两条都写进了探针源码注释和本文档，因为**下一个接手的很可能再踩一遍**。

## 四、Go 绑定：127 → 1

### 4.1 先说坏消息：改之前整包编不过

```
.\dll_windows.go:484:2: undefined: procFindColorBlockExS
.\dll_windows.go:485:2: undefined: procFindLineExS
```

两个 proc **只在 `bindProcs()` 里赋值、`var` 块漏了声明** —— 说明 go 绑定已经很久没被编译过
（没有 go 使用者，也没有 CI）。本轮一并修掉。

### 4.2 工具链

`go.mod` 要求 `go 1.26.2`，本机原本没有 go。装了 **Go 1.26.11** 到
`C:\Users\lc\.workbuddy\binaries\go126\go`（注意：不要覆盖解压到已有版本目录，
混合解压会让 stdlib 出现 `dumpregs redeclared` 这类假错误 —— 本轮踩过一次）。

```powershell

$env:GOPATH="C:\Users\lc\.workbuddy\binaries\go126\gopath"
go build ./... ; go test -run TestExtraBindingsSmoke -v
```

### 4.3 生成方式

`scripts/gen_go_bindings.py` 从 `include/op_c_api.h` 解析签名，机械生成
`bindings/go/extra_windows.go`（126 个方法 + proc 声明 + `bindExtraProcs()`），
`dll_windows.go` 只在 `bindProcs()` 末尾加一行调用。

类型映射（对齐既有 `*_windows.go` 写法）：

| C | Go |
|---|---|
| `int` / `long` | `int` → `uintptr(x)` |
| `intptr_t` | `uintptr`（参数）/ `int64`（返回） |
| `long long` | `int64` → `uintptr(x)` |
| `double` | `float64` → `f64Arg(x)` |
| `const wchar_t *` | `string` → `strArg(x)` / `wcharString(ret)` |
| `const void*` / `unsigned char*` + size | `[]byte` → `bytesPtr(b), uintptr(len(b))` |
| `int *x` / `double *v` | 追加 out 返回值 |

**生成器必须幂等**：第一次跑完再跑一次会生成 0 个方法，因为产物里的
`dll.NewProc("OpXxx")` 被当成"已绑定"。已在扫描时跳过自身产物。
