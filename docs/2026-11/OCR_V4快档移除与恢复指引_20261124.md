# OCR V4 快档移除与恢复指引（2026-11-24）

## 0. 结论

- 2026-11-24 第六十八批：移除 PP-OCRv4 快档，`SetOcrEngine("v4"/"V4")` 兼容回落到 v6；四 DLL 重编并同步到 `bin/`、bindings、OPTool 各目录。
- v4 **无独占功能**：`OcrEx2` 逐字坐标、`ExtractWordRects` 点阵字块切取两档一致；小图颜色二值化智能选路 v6 **8/8** vs v4 **3/8**。
- 唯一退化：单行小图 v4 **21~40ms** vs v6 **33~72ms**；大图/长行 v6 反而更快。
- 同批另改：CLS（0/180 度方向分类）默认由**开**改**关**（`--cls=1` 可开），实测省约 2ms/次。
- 本指引基于 HEAD `3585d4ece3a37f793609dc1ee68ee7a40b269679`；写文档时改动**尚未提交**。

## 3. 恢复路径 B：只恢复 v4 档，保留 CLS 默认关闭

适用：只想拿回单行小图速度，不想要 180° 翻转检测的默认开销。按下列点逐项改：

1. `libop/CMakeLists.txt`：在 `OCR_MODEL_CLS` 之后加回
   ```cmake
   set(OCR_MODEL_V4_DET "${_op_ocr_models_dir}/v4_backup/ch_PP-OCRv4_det_infer.onnx")
   set(OCR_MODEL_V4_REC "${_op_ocr_models_dir}/v4_backup/ch_PP-OCRv4_rec_infer.onnx")
   set(OCR_MODEL_V4_KEYS "${_op_ocr_models_dir}/v4_backup/ppocr_keys_v1.txt")
   ```
2. `libop/ocr/ocr_models.rc.in`：加回 `#define IDR_OCR_V4_DET 201` / `_REC 202` / `_KEYS 203` 及三条 `IDR_OCR_V4_* OCRMODEL "@OCR_MODEL_V4_*@"` 资源。
3. `libop/ocr/ocr_models.h`：加回同三个 ID 宏（201/202/203）。
4. `libop/ocr/OnnxOcrEngine.cpp`：
   - `Impl` 加回 `bool use_v4 = false;`；**`cls_on` 保持 `false`**。
   - `load()`：`id_det/id_rec/id_keys` 改回 `use_v4 ? IDR_OCR_V4_* : IDR_OCR_*`，`m_cls` 仍共用 `IDR_OCR_CLS`。
   - 加载日志改回 `"models loaded (" << (use_v4 ? "v4" : "v6") << ")"`。
   - `init()`：`(void)engine;` 改回 `m_impl->use_v4 = (engine == L"v4");`。
   - **不要动** `if (!cls_set) m_impl->cls_on = false;`（这是本次新默认）。
5. `libop/ocr/OcrService.cpp`：`normalize_engine_name()` 加回
   ```cpp
   if (eng == "v4" || eng == "V4") return "v4";
   ```
   并删掉 `init_unlocked()` 里的 `v4 fast tier removed, falling back to v6` 提示、注释恢复为「v4 → 快档」。
6. `libop/ocr/OcrService.h`：注释恢复为 `..."v4" -> 快档`。

重建、同步、验收同路径 A。差异：默认引擎日志仍是 `cls=off`，`SetOcrEngine("v4")` 日志为 `cls=off`（旧行为），v6 可用 `--cls=1` 手动开。
