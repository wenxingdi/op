## 二、各模块成果

### 2.1 OCR：P1 FindStr 增强 + P3 耗时自省

**P1：`OpFindStrBatch` / `OpFindStrEx2`**（COM 442/443）

旧 `FindStr` 是纯子串包含——找 `909` 会命中 `1909`/`9090`；只能返回整行左上角。
新接口解决：

| 能力 | 说明 |
|---|---|
| `match=exact/prefix/suffix/regex` | 精确/前缀/后缀/正则 |
| `fuzzy=1..3` | 编辑距离容错（形近字） |
| `max_hits` / `ci` / `confirmed_only` | 条数、大小写、只看未贴边行 |
| **字符级定位** | 用 P0 逐字坐标返回 `cx1/cx2`，精确到被找子串自己的框 |

实测：`击倒机关兽909米` 找 `909` → 行框 0–388，而 `cx1=247 cx2=344`，精确落在 909 上。

> 修正了交接文档一处描述：它说「N 个目标要跑 N 次 OCR」，
> 实测旧 `FindStrEx` 已支持一次传入。P1 的真实价值是**按目标独立配置 + 字符级定位 + 返回全部命中**。

**P3：`OpOcrLastProfile`**（COM 444）

```
{"total_ms":169.99,"det_ms":125.08,"cls_ms":2.28,"rec_ms":22.82,"rec_width":576,...}
```

顺带把 P2 的动态 rec 宽度变成可观测值。**数据直接指出 det 才是小图 OCR 的瓶颈**（125ms vs rec 23ms）。

### 2.2 OpenCV：尺度精修接入金字塔

**先量后改，三次假设全被实测推翻**：

| 假设 | 实测 |
|---|---|
| 尺度粗筛没实现 | 错，探针/金字塔缓存/自适应降采样/快路径**全部已存在** |
| 调用次数太多（10 次） | 错，实测只做 **3 次**全分辨率精修 |
| 探针阶段慢 | 错，探针仅 35ms（占 3%） |

**真因**：单次全分辨率匹配要 330ms；`refineScaleCandidate` 调的是纯暴力匹配，
而 `MatchTemplate(named)` 走金字塔只要 76ms。**尺度精修这条路从未接过金字塔。**

**改动**：接入金字塔 + `pyramidFindFirstMatch` 候选数 12→4。

| 场景 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| named_match | 76ms | **43ms** | -43% |
| hard_scale_auto | 331ms | **60ms** | **-82%** |
| scale_manual | 718ms | **337ms** | -53% |
| scale_auto | 1208ms | **755ms** | -37% |
| direct_candidates | 371ms | **261ms** | -30% |
| game_coin_all | 621ms | **447ms** | -28% |

> **顺手挖出一个真实测试盲区**：故意把金字塔坐标的 ROI 原点写错，
> 原 34 个 OpenCv 用例**仍然全绿**——因为唯一相关用例用 18×18 源图 + 4×4 模板，
> `shouldTryPyramid` 不成立，金字塔分支从未被执行。
> 补测又踩两坑（条纹 1.5 倍偏 109px；ROI 取整图时 `roi.x` 恒为 0 测不出），
> 最终新增 `PyramidMatchKeepsAccurateCoordinatesOnLargeImage`（大图 + **带偏移 ROI**），
> 实测 ROI 原点写错 → 偏差正好 900px → 用例 RED。

### 2.3 内存：图像句柄注册表（从零新建）

**缺口实证**：`OpLoadImageFromMem` / `OpFreeImage` / `OpGetImageData` / `OpCropImage` /
`FromMem` / `FromPtr` / `ImageHandle` 在三个接口文件里**全部 0 命中**。

后果：所有识别入口要么吃"屏幕区域"要么吃"文件路径"，
调用方拿到像素后必须**落盘再读盘**（实测 50~200ms，内存注册 <5ms）。

**新增 9 个接口**（COM 445~453）：`LoadImageMem` / `LoadImageBmp` / `FreeImage` /
`FreeAllImages` / `GetImageSize` / `GetImageData` / `CropImage` / `FindStrMem` / `GetImageCount`。
句柄形态 `img:<n>`，与既有 `pic:<路径>` 风格一致。

**关键决策**：注册表满时**拒绝新增、不淘汰既有句柄**（与 `g_pic_cache` 满了清空有意不同——
显式创建的句柄突然失效是更糟的失败模式）；注册后像素不可变（多线程并发读安全）。

> 内存读写侧（`OpFindData` 全家桶）本身质量已很好：分块读、跨块防漏检、
> 锚点优化、地址回绕保护。**本期只补图像句柄这块地基**，没动那些。

### 2.4 YOLO：过滤/截断 + 两处修正

**引擎侧质量已很好**（类别感知 NMS、v8/v11 解析、metadata labels 自动加载、异常保护全覆盖），
**缺口全在 API 层**。

**新增**（COM 454/455）：`OpYoloDetectEx2` + `OpYoloDetectFromFileEx2`

```json
{"class_ids":[0,2],"labels":["person"],"max_results":20}
```
- `class_ids` 与 `labels` 取**并集**（取交集会让"以为能命中"变空结果）
- `max_results` 按 confidence **降序**截断

**两处修正**：
1. **坐标口径**：`+= x1` → `+= x1 + _dx`。原实现缺客户区补偿，窗口模式下与 OCR/找图**错位**。
   （行为变更，已标注）
2. **JSON 改 `op::json` DOM**：原为手拼字符串。

> 为什么加文件版 Ex2：屏幕版依赖绑定窗口，测试机没有可绑定窗口，
> 过滤逻辑无法闭环。文件版让过滤/截断能用**真实模型**验证。

### 2.5 音量：从零新建（WASAPI）

**缺口实证**：仓库内 `*audio*`/`*volume*`/`*sound*` 文件 **0 个**。

**8 个接口**（COM 456~463）：会话级（`QueryWindow`/`QueryPid`/`GetPidFromHwnd`/
`SetSessionVolume`/`SetSessionMute`）+ 系统级（`GetSystemVolume`/`SetSystemVolume`/`SetSystemMute`）。

**真机闭环验证**（子进程播放 440Hz 循环音频）：

```json
{"ok":1,"code":0,"found":true,"playing":true,"volume":1,"peak":0.194206}
SetSessionVolume(0.42) -> 读回 0.420
```

> **这组数据印证了最关键的语义**：`volume=1`（滑块满格）而 `peak=0.194`
> —— **滑块值与出声大小无关**，判断"有没有声音"必须看 `peak`。

## 三、本轮发现的三个"看不见的坑"（都已固化进 CLAUDE.md）

这三个都不是功能 bug，但每一个都能让人白花几小时。

### 3.1 构建缺陷：改头文件不触发重新编译 ⚠ 影响所有人

**根因**：`cl /showIncludes` 输出是 **UTF-8**，CMake 写进 `build.make` 的
`--filter-prefix` 是 **GBK**。字节不匹配 → 依赖扫描一行都过滤不到 →
`*.obj.d` 恒为 0 字节 → **头文件不在依赖图里**。实测 233 个 `.obj.d` 里 86 个是空文件。

**危害实证**：第一次跑反向验证，5 个场景有 3 个"改错后测试仍全绿"，
第一反应是"断言恒真"，实际是**补丁打在 `.h` 上但测试 obj 根本没重编**。
**如果没有追查，本轮的"反向验证通过"会是假的。**

**已修复**：`_wb_build.py` 加 dep-guard 自动兜底（构建前清理 0 字节依赖的 obj）。

### 3.2 DSH 沙箱下原生进程写不了 `%TEMP%`

新会话首次跑 `OcrEx2Test` **挂了 8/9**，全是 `path.empty()`。
不是代码问题：DSH 拦截原生子进程对 `%TEMP%` 的写入（`err=5`），测试画不出临时 BMP。
`$env:TEMP` 指到工作区即全绿。

### 3.3 新增 C API 必须检查导出名是裸名（只坑 x64）

x64 的 C 导出靠 `op_c_api.h` 里的 `extern "C" {` 块。若把新声明**追加在头文件末尾
（`#ifdef __cplusplus } #endif` 之后）**，会变成 **C++ 修饰名**：

```
?OpYoloDetectFromFileEx2@@YAPEB_WPEAUop_c_context@@PB_WNN1PEAH@Z
```

**后果：C++ 测试照常链接下来全绿，但 Python/易语言按裸名 `GetProcAddress` 调不到**
——测试绿而功能不可用。x86 靠 `.def` 生成裸名，所以只坑 x64。

本轮实际踩到过（YOLO 的 `OpYoloDetectFromFileEx2`），已修正。
自查：`dumpbin /exports ... | findstr <名字>`，必须是裸名。

## 五、诚实记录：本轮没做到的部分

### 5.1 YOLO 的 `max_results` 截断**未能闭环验证**

`yolo_meta_test.onnx` 是脚本生成的极简模型，**NMS 后恒定只输出 1 条**。
试过 320×240 / 1280×960 / 1280×1280 四块拼贴、conf 低到 `0.0001`，始终 `total=1`。
所以"截断到小于总数"这一支**无法用真实数据验证**。

处理方式：用例改成 `total>1` 时断言真实截断（**换台机器会自动生效，不会假绿**），
`total==1` 时 `GTEST_SKIP` 并写明原因。

### 5.2 全量 5 个失败：均为既有环境问题（已逐条证明）

```
MouseKeyTest.BindWindowDxSuffixDoesNotPolluteSessionAttr      baseline FAIL
WindowStateTest.DxBindToSameIntegrityWindowStillSucceeds      baseline FAIL
HookCaptureTest.BindLoadsMissingGraphicsAndInputModulesOnDemand baseline FAIL
WgcTest.NormalDxgiMaximizeAfterBindCapturesClippedClientArea  baseline FAIL
WgcTest.RepeatedBindUnbindAndMaximizedRepeatedCapture         单独跑 PASS（既有 flaky）
```

全部用 `git stash` 在**干净基线**复现过，与本轮改动无关（DX/Hook/WGC 需要真实游戏窗口与提权环境）。

另：`WindowServiceTest.RunAppLaunchesShortcut` 本机必崩（`0xC0000005`，基线同样崩），
全量回归时用 `-WindowServiceTest.RunAppLaunchesShortcut` 排除。

### 5.3 我自己的三个失误（都修了，如实记录）

1. **PowerShell 行号编辑两次差点毁文件**：一次 `$lines` 为空导致
   `ImageSearchService.cpp` 被覆盖成 274 行（`git checkout` 救回）；
   一次引号转义把脚本自身解析坏。**改用 Python 脚本插入**，
   内置"读入校验 → 备份 → 写入复检 → 自动回滚"。
2. **测试写法踩了 C API 缓冲区复用**：`OpLoadImageMem` 返回的 `const wchar_t*`
   指向复用缓冲区，下次调用就失效。测试里没立刻复制成 `std::wstring`，
   导致句柄变空串，表现极像"句柄传递丢了"。
3. **自己制造的 COM 污染**：音量模块的 STA 用例第一版在开头无条件
   `CoUninitialize()` 想"确保干净"，扣掉了后续用例依赖的 COM 计数，
   让 `RealSessionReadWriteRoundTrip` 偶发失败。改为探针判断后稳定全绿。

### 7.2 最值得优先做的下一步

**内存直操作二期**（`OpOcrFromMem` 等）。理由：
- 地基（`img:` 句柄 + `acquire_image`）已就绪
- 实现模式简单：把"截屏"换成"取句柄"，复用现有屏幕版实现
- 收益明确：调用方已有像素时省掉落盘往返（50~200ms → <5ms）

### 7.3 开发纪律（本轮验证有效）

1. **先量后改**。本轮 OpenCV 三次假设全错，全靠探针纠正。没有探针的"优化"大概率是自嗨。
2. **区分"纯性能改动"与"语义改动"做反向验证**：前者应保持 GREEN（证明等价），后者应 RED。
3. **改头文件或怀疑"修复没生效"时，先查 obj 时间戳**。这条比任何调试技巧都省时间。
4. **大文件结构性插入用 Python 脚本**，不要用 PowerShell 行号操作。
5. **如实记录没做到的部分**。`GTEST_SKIP` + 写明原因，比写个"跑了但没真跑"的用例强得多。
