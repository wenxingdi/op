### 3.2 反向验证

把 `_ffi.py` 里 `OpGetColorFromMem` 的签名名改错一个字符：

```
op.errors.DllLoadError: ...op_c_api_x64.dll is missing a required C API export
```

加载即失败（`_bind()` 会对**每个**声明做 `getattr` 校验），说明这批签名不是摆设。
恢复后冒烟重新全绿。

> 顺带确认了一个有用的事实：**签名表里写错一个名字，绑定在加载期就炸**，
> 不会等到调用期才发现 —— 这是这批绑定的天然护栏。

### 3.3 过程中修正的三处**断言口径错误**（不是代码 bug，如实记录）

首轮冒烟 8 项红，逐条查证后全是我的断言写错，接口本身是对的：

| 接口 | 我错以为 | 实际契约（与屏幕版一致） |
|---|---|---|
| `find_color_ex_from_mem` / `find_multi_color_ex_from_mem` | 返回 JSON | **大漠串** `"x,y|x,y|..."` |
| `find_color_block_ex_from_mem` | 返回 JSON | 单点串 `"x,y"` |
| `find_pic_ex_from_mem` | 未找到返回 JSON | 未找到返回**空串** |
| `ocr_ex2` / `ocr_from_mem_ex2` | 纯色图上返回 JSON | 无文字返回空串 / `[]` |

另外 YOLO 那两项：一开始拿 16×8 的图当靶子，40×40 的框被缩成 `h=0` 当退化框丢掉
（只剩 2 条），改 640×480 后 `total=4` 正确 —— **靶子选错**，不是绑定缺陷。
