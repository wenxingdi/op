> 依据：`OLA_vs_OP_能力对比与高收益清单_20261122.md` §五 的高收益五项。
> 用户指定顺序：① 多实例并发验证 ② DrawGui 最小组 ③ YOLO 增强 ④ 汇编补全 ⑤ 录制回放/主从同步/时间轴层。

## 0. 先修正规划里的两处错误（重要）

动手前读代码发现，我上一份报告的两条「缺口」判断**不准确**，必须在此更正：

| 原判断 | 实际 | 影响 |
|---|---|---|
| 「屏幕绘制 44 接口，OP 零覆盖」 | **OP 已有最小组**：`DrawRect`/`DrawLine`/`DrawText`/`DrawClear`/`DrawSetVisible`（`libop/op/OpDraw.cpp`，2026-10-15 P2 落地，GDI+ + 分层窗口 + 穿透） | ② 不是从零做，而是**补齐最小组里真正缺的三种图元 + 绑定窗口内绘制** |
| 「多实例并发未验证」 | **已有 4 条基线**（`tests/concurrency_test.cpp`，2026-11-21）：多句柄读色 / 同句柄注册表 / 同句柄内存找色 / 同句柄 OCR。且 `libop.h` 顶部**已写明**「单实例非线程安全，每线程一个实例」 | ① 不是从零验证，而是**补足未覆盖的路径 + 把已知结论做成可诊断的事实** |

这两条更正决定了 ① 和 ② 的真实工作量比报告里小得多，但对「做什么」影响很大：
① 的价值在于**把"能用/不能用"从口头约定变成可执行断言**，② 的价值在于**补 `DrawCircle`/`DrawImage`/`DrawRectEx` 这三条真正天天用的**。

## 2. A 批：多实例 / 并发（本轮实施）

### 2.1 要做的事

| # | 项 | 判据 |
|---|---|---|
| A1 | **多实例并发 OCR**（每线程独立 `OpCreate`） | 8 实例 × 2 轮，全部返回非空且文本一致；不崩 |
| A2 | **多实例并发 YOLO** | 4 实例 × 2 轮，结果条数/坐标一致（引擎单例串行，验证不串味） |
| A3 | **同实例并发写 `string_result` 的防护** | 同实例两线程并发取字符串 → 断言"**不出错但要能测出来**"：用 `OpConcurrencyInfo` 报出实例级调用计数，证明串行化生效 |
| A4 | **实例销毁与全局资源竞态** | A 线程 `OpDestroy`，B 线程同时用另一实例 → 不崩、图像注册表计数回到基线 |
| A5 | **绑定窗口并发** | 两实例绑不同窗口（用同进程两个测试窗口），互不串坐标 |
| A6 | `OpConcurrencyInfo` | 返回 JSON：`{"instances":N,"image_count":M,"busy":0/1,"last_serialized_ms":..}` |

### 2.2 已知约束（不改变，只写明）

- **单实例非线程安全**（`libop.h` 顶部既有约定）。本批**不改成线程安全**——把 348 个方法逐个加锁会显著掉性能且有死锁风险，和大漠语义也一致。
- 本批要做的恰恰是**让这条约束可执行**：加一把**实例级非阻塞互斥**，检测到同实例重入时置 `busy` 并记日志，把"静默污染"变成"可观测的串行/告警"。

> 这是有意的**行为收敛**：同实例并发从"可能互相污染结果"变成"排队执行 + 可诊断"。

## 3. B 批：DrawGui 补齐

| 接口 | 说明 | 与 OLA 对应 |
|---|---|---|
| `DrawCircle(x, y, r, color, width, fill)` | 现有 `DrawCmdType` 只有 Rect/Line/Text，加 Circle | `DrawGuiCircle` |
| `DrawImage(x, y, file, alpha)` | 叠加层画图片（GDI+ 直接 LoadImage） | `DrawGuiImage` |
| `DrawRectEx(x, y, w, h, mode, line)` | 画在**绑定窗口客户区**、独立透明窗口、随窗口移动、**不进 DX 截图** | `DrawGuiRectangleEx` |
| `DrawClearBind` | 只清掉绑定窗口那批图元（与 `DrawClear` 屏慕版分开） | `DrawGuiClearBind` |
| `DrawGetCount` | 诊断：屏慕/绑定两套各多少图元 | `DrawGuiGetDrawObjectType` 精神 |

**关键实现点**：`DrawRectEx` 需要按绑定窗口矩形定位一个子覆盖层，并订阅窗口移动/大小变化（`SetWinEventHook`）跟随；坐标用**客户区**口径，和找色/鼠标一致。

## 4. C 批：YOLO 增强

### 4.1 现状（已读 `OnnxYoloEngine.cpp` / `YoloDetector.h`）

- 引擎抽象只有一个方法 `detect(...)`，输出 `vyolo_rec_t`（**只有框 + class + conf**）
- 解码器 `Impl::decode()` 写死 `oshape.size()==3` 的 `[1,nattr,nanch]` 布局 → **只能吃检测模型**
- 线程：`OnnxYoloEngine` 的 `SetIntraOpNumThreads` 已支持；但 `YoloDetector::detect` 用 `m_mutex` **全局串行**（注释说"推理本身重负载，串行影响可忽略"）
- 配置入口：`--conf= / --iou= / --labels= / --threads=`；无设备选择、无模型元信息查询

### 4.2 本批范围（明确不做全五类）

| 做 | 不做 | 理由 |
|---|---|---|
| `YoloSegment`（检测 + 掩码） | `Pose`（关键点） | 姿态模型输出 `[1, 56, 8400]` 与检测同构，但关键点语义/骨架连线需要额外规格；**Segment 的 ROI 提取价值更高、复用检测解码器** |
| `YoloClassify`（整图分类） | `Obb`（旋转框） | 分类输出 `[1, nc]`，与检测完全不同但实现最简、且能立刻用上现有模型资产 |
| `YoloGetModelInfo`（模型元信息 JSON） | 多模型热切换 | OLA 的「句柄式多模型」是整套生命周期设计，牵动引擎单例结构；本批先把**单模型的 task 维度**打通 |
| 引擎抽象 `task` 化 | TensorRT / NCNN 后端 | 需要额外依赖链，属基建级变更 |

### 4.3 接口草案

```
YoloSegment(x1,y1,x2,y2, conf, iou, json_options, retjson, ret)   // 掩码以 RLE 或 polygon 输出
YoloClassify(x1,y1,x2,y2, topk, retjson, ret)                     // [{"class_id","label","score"}]
YoloGetModelInfo(retjson, ret)                                    // {"task","input_w","input_h","names":[...],"threads"}
```

## 5. D 批：汇编补全

| 接口 | 实现 | 风险 |
|---|---|---|
| `Assemble(code, retjson)` | keystone（vcpkg 有 port） | 依赖新增 |
| `Disassemble(bytes_hex, addr, count, retjson)` | capstone | 依赖新增 |
| `AsmCall(hwnd, addr, argv_json, retjson)` | 复用现有远程线程能力（`memory/` 已有 `VirtualAllocEx`/`CreateRemoteThread` 同族调用） | **最高风险**：要注入并执行代码。首版限定 x64、只支持寄存器无关的简单调用（参数走栈/寄存器按 ms x64 → SysV 需注意 ABI） |

**若 keystone/capstone 拉取失败**：降级为「先做 `AsmCall`（不依赖第三方）+ `Disassemble` 用 Windows 自带 `DbgHelp`/`dumpbin` 不可行 → 则 D 批只交付 `AsmCall`，`Assemble/Disassemble` 记录为阻塞项**如实上报**，不假装完成。

## 6. E 批：时间轴层

| 组 | 接口 | 形态 |
|---|---|---|
| 采集开关 | `InputSyncEnable(0/1)` | 进程级事件总线 |
| 监听 | `SetInputMonitor(callback)` + 回调类型 | 与 OLA `InputMonitorCallback` 同构 |
| 录制 | `InputRecord(START/STOP)` + `InputRecordGetPath` | 落盘 JSONL（`{t,type,vk,x,y,wheel,flags}`） |
| 回放 | `InputPlayback(LOAD/START/STOP/FREE, path, speed, loop)` | 时间轴按 `t` 等比缩放 |
| 主从 | `InputSyncLink(master, slave, enable)` | 主实例事件异步投到从实例 |

**关键设计**：录制入口必须挂在**所有输入 API 的出口**（Mouse/Key 各方法统一走一个 `input_event_bus`），否则录不全。
