## 三、三个"看不见的坑"（必须先知道，否则白花几小时）

### 3.1 改 `.h` 不触发重新编译 ⚠ 最重要

`cl /showIncludes` 输出 UTF-8，CMake 写进 `build.make` 的前缀是 GBK，
依赖扫描失效 → 233 个 `.obj.d` 里 86 个是空文件 → **头文件不在依赖图里**。

`_wb_build.py` 已加 dep-guard 自动兜底（构建前清理空依赖的 obj）。
**但如果改的是被大量 TU 包含的头文件（如 `OpCaptureHelpers.h`），一次重建要 10+ 分钟**——这是正常的，不要以为卡住了。

自查是否真的重编了：
```powershell
(Get-Item <对应>.obj).LastWriteTime   # 必须晚于你改文件的时间
```

### 3.2 DSH 沙箱下原生进程写不了 `%TEMP%`

不设 `$env:TEMP` 时，所有用 `GetTempBmpPath` 落盘的用例会**伪失败**（满屏 `path.empty()`）。
不是代码问题。

### 3.3 新增 C API 必须检查导出名是裸名（只坑 x64）

x64 的 C 导出靠 `op_c_api.h` 里的 `extern "C" {` 块。
**把声明追加在头文件末尾（`#ifdef __cplusplus } #endif` 之后）→ 变成 C++ 修饰名**
→ C++ 测试全绿但 Python/易语言 `GetProcAddress` 调不到。

自查：
```powershell
& "<VS>\VC\Tools\MSVC\14.44.35207\bin\Hostx64\x64\dumpbin.exe" /exports `
  build\nmake-x64-Release\libop\op_c_api_x64.dll | Select-String "你的函数名"
# 必须是裸名，不能是 ?Xxx@@YA...
```

`scripts/probes/insert_*.py` 都已经处理了这一点（插在闭合前 + 校验位置）。

## 六、内存直操作二期（当前任务）

### 6.1 做了什么

新增 14 个 `*FromMem` 接口，让所有识别入口都能直接吃 `img:` 句柄：

```
OcrFromMemEx2 / OcrAutoColorFromMemEx2
FindPicFromMem / FindPicExFromMem
FindColorFromMem / FindColorExFromMem
GetColorFromMem / CmpColorFromMem / GetColorNumFromMem
FindMultiColorFromMem / FindMultiColorExFromMem / FindColorBlockExFromMem
YoloDetectFromMem / YoloDetectFromMemEx2
```

### 6.2 核心机制（复用屏幕版，零逻辑复制）

`libop/op/OpCaptureHelpers.h` 新增 `with_mem_region`，与 `with_captured_region`
**签名完全一致**：

```
with_captured_region：截屏 -> _src，set_offset(x1,y1)
with_mem_region     ：从句柄裁区域 -> _src，set_offset(0,0)，回传区域原点
```

所以内存版门面 = 屏幕版门面换一个上下文函数，**行为一致性是结构保证**。

### 6.3 坐标语义（重要）

| 项 | 说明 |
|---|---|
| 入参 x1..y2 | **图像内坐标**（相对句柄左上角） |
| 区域 (0,0,0,0) | **整张图**（与屏幕版不同——屏幕版全 0 无可截区域） |
| 出参坐标 | **图像内绝对坐标**（已加回区域原点，与屏幕版加回 `_x1+_dx` 对应） |

### 6.4 顺带完成的重构

YOLO 的检测核心（过滤/截断/JSON 构建）原本在 `OpYolo.cpp` 的匿名命名空间里，
跨 TU 不可见。抽出到 `libop/op/YoloDetectCore.h`，屏幕版与内存版共用一份。

## 九、开发纪律（本轮验证有效，务必延续）

1. **先量后改**。OpenCV 那轮三次假设全错，全靠探针纠正。没探针的"优化"大概率是自嗨。
2. **区分"纯性能改动"与"语义改动"做反向验证**：前者应保持 GREEN（证明等价），后者应 RED。
3. **改头文件或怀疑"修复没生效"时，先查 obj 时间戳**。
4. **大文件结构性插入用 Python 脚本**（`scripts/probes/insert_*.py`），
   不要用 PowerShell 行号操作——本轮两次差点毁文件（`git checkout` 救回）。
   脚本内置"读入校验 → 备份 → 写入复检 → 自动回滚"。
5. **反向验证必须真的物理变红**，"改错后仍全绿"有两类原因：
   - 断言太弱（加强断言）
   - **改错没进二进制**（查 obj 时间戳）
6. **如实记录没做到的部分**。`GTEST_SKIP` + 写明原因，比写个"跑了但没真跑"的用例强得多。
