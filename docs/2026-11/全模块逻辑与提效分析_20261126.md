### OCR（libop/ocr + op/OpOcr.cpp）— 近两天改动最密集
- 状态：命名已归一（autoocr 正名 + 6 别名告警），空颜色误走二值化已修，HTTP 后端已删。
- ✅ **帧缓存 memo（2026-11-26 已实施，默认关）**：轮询场景（每隔几百 ms 对同一区域 OCR）
  画面未变时重复 det+rec。实现：ImageSearchService 单槽结果 memo，指纹 = 区域像素 FNV-1a 哈希
  （与 OpIsDisplayDead 同口径）+ kind/color/sim + 引擎代次 + 字库代次（全局 epoch，SetDict/ClearDict/
  AddDict 等 4 处自增）+ 识别设置（pre_scale/bridge/auto_pick_color/二值化四参数）；任一变更自动失配。
  OCR/OcrEx/ocr_auto_color(_line/_ex)/ocr_ex2/ocr_auto_color_ex2/OcrAuto 8 入口统一经 ocr_memo_wrap；
  OcrAutoFromFile 原直调 OcrFree 绕过 memo，已改经 OcrAuto（口径不变）。开关：SetOcrEngine argv
  `--ocr_memo=1` 或 op::Op::SetOcrMemoEnabled；命中率诊断 GetOcrMemoHits/Misses。
  测试 OcrFrameMemo* 6 例经 op::Op + FromFile 喂图，无需引擎即可验证命中/失效语义。
- 🟡 任务族提示：Classify/Segment/Pose/Obb 无 Ex2 过滤变体（昨天已记录，等需求）。
- 逻辑面未发现新问题：智能选路、三段式颜色策略、字库协同均有测试覆盖。

### 图色（libop/image）— FindPic/FindColor/FindStr 内核
- ✅ **pic 缓存 LRU 淘汰（2026-11-26 已实施）**：`store_cached_pic` 满时不再整体清空，
  改为淘汰最久未用条目（平行 tick map 记 LRU 时间戳，O(n) 扫描仅在淘汰瞬间发生，n≤上限可忽略）。
  `find_cached_pic` 命中时升级 unique_lock 刷新时间戳；`erase_cached_pic`/`clear_pic_cache` 同步清 tick。
  测试 `SetPicCacheMaxEvictsLeastRecentlyUsed` 已改写为精确断言 LRU 语义（区别于旧"全清"）。
- 其余逻辑扎实：多线程 shared_mutex 快照、越界防御、ExS 聚类版均有测试。

### 内存（libop/memory）
- ✅ **远程句柄缓存（2026-11-26 已实施，默认关）**：ProcessMemory 实例每次 API 调用
  临时构造，远程路径每次都 BlackBone Attach = Detach(CloseHandle)+OpenProcess；汇编循环
  连续 patch（上千次读写）就有上千次句柄往返。实现：全局缓存 pid → 常驻 Process，
  10s 空闲 TTL + GetProcessTimes 创建时间比对（防 pid 复用指向新进程）+ 容量 8 最久未用
  淘汰；BlackBone ProcessModules::GetModule 自带缓存校验与重枚举，长驻不会拿到过期模块表；
  Disable/Clear 时统一 Detach。开关 SetMemHandleCacheEnabled（默认关），命中率诊断
  GetMemHandleCacheHits/Misses，四层绑定（C++ Op/C API/ctypes/swig）齐全。
  测试 RemoteHandleCacheHitsAcrossRepeatedReads：plain_carrier 独立进程远程读，
  miss→hit 计数与缓存前后读值一致性均验证。
