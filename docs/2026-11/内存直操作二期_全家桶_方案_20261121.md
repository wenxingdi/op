## 三、核心设计：复用屏幕版实现，不复制逻辑

### 3.1 结构保证

新增 `with_mem_region`（`OpCaptureHelpers.h`），与 `with_captured_region` **签名完全一致**：

```
with_captured_region(ctx, x1,y1,x2,y2, fn):
    截屏(x1,y1,w,h) -> image_proc._src
    set_offset(x1, y1)
    fn()

with_mem_region(ctx, handle, x1,y1,x2,y2, fn):
    从 handle 裁出 [x1,y1,x2,y2) -> image_proc._src
    set_offset(0, 0)
    fn()
```

于是内存版门面可以**逐行照抄屏幕版**，只把 `with_captured_region` 换成 `with_mem_region`：

```cpp
// 屏幕版
void Op::FindPicEx(x1,y1,x2,y2, ...) {
    with_captured_region(ctx, x1,y1,x2,y2, [&]{ image_proc.FindPicEx(...); });
}
// 内存版（唯一差别）
void Op::FindPicExFromMem(handle, x1,y1,x2,y2, ...) {
    with_mem_region(ctx, handle, x1,y1,x2,y2, [&]{ image_proc.FindPicEx(...); });
}
```

**这是"行为与屏幕版严格一致"的结构保证**，而不是靠测试去发现不一致。

### 3.2 坐标语义

| 项 | 屏幕版 | 内存版 |
|---|---|---|
| 入参 x1..y2 | 客户区坐标 | **图像内坐标**（相对句柄左上角） |
| 出参坐标 | 客户区坐标（`_x1 + _dx`） | **图像内坐标**（偏移全 0） |
| 区域 (0,0,0,0) | 无效（宽高 ≤0） | **整张图**（脚本习惯写法） |

> 内存版把 `(0,0,0,0)` 当整图是**有意的不一致**：
> 脚本里传全 0 想表达"整张图"很自然，而屏幕版全 0 确实没有区域可截。
> 这条差异写进文档与用例。

### 3.3 边界

| 场景 | 行为 |
|---|---|
| 句柄无效/已释放 | 不执行回调，返回默认失败值（`-1` / 空串 / `ok:0` JSON） |
| 区域越界 | 自动 clamp；clamp 后为空则不执行 |
| 区域为整图 | **零拷贝**复用原像素（性能） |
| 局部区域 | 逐行 memcpy（与一期 `CropImage` 同法） |

## 四、接口形态（对齐屏幕版签名 + 前置 handle 参数）

内存版一律**在参数最前面加 `image_handle`**，其余参数与屏幕版逐字相同：

| 屏幕版 | 内存版 |
|---|---|
| `OpFindPic(x1,y1,x2,y2, files, delta, sim, dir, &x,&y)` | `OpFindPicFromMem(handle, x1,y1,x2,y2, files, delta, sim, dir, &x,&y)` |
| `OpOcrEx2(x1,y1,x2,y2, color, sim)` | `OpOcrFromMemEx2(handle, x1,y1,x2,y2, color, sim)` |
| `OpYoloDetectEx2(x1,y1,x2,y2, conf,iou, opts)` | `OpYoloDetectFromMemEx2(handle, x1,y1,x2,y2, conf,iou, opts)` |

**这样设计的好处**：调用方只需在现有调用前插一个句柄参数，其余完全照抄；
易语言侧也就是多传一个 BSTR。

### 9.4 反向验证：第一轮 1/4，根因**不是断言弱**（重要记录）

第一轮 4 个场景只有 1 个变红。逐条排查后确认——**代码有防御纵深**，
单点改动被下游防线兜住了：

| 场景 | 为何没红 | 结论 |
|---|---|---|
| 删掉 `set_offset(0,0)` | 新建 Op 实例的 `_x1/_y1` 恰好是 0，结果不变 | 无副作用，测不出 |
| 判空改 `right < left` | `w=0` 时 `create(0,h)` 仍成功，扫描 0 列 = 0 像素 | 下游兜住 |
| 绕过首个句柄判空 | 空图 `right<=left` 仍为真，被后面的判空拦下 | 下游兜住 |

**说明**：这不代表断言弱，而代表实现有多层保护。
但也暴露了**测试覆盖面不足**：每个用例都新建 `CApiHandle`，掩盖了"同一实例状态残留"这一类问题。

**补充的两个用例**（本轮新增）：
- `RepeatedCallsDoNotAccumulateOffset`：同一实例连续查不同子区域
- `DegenerateRegionIsRejected`：宽/高为 0 的区域
