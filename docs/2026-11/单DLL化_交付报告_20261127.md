## 技术路径与排坑记录（复用价值高）

1. **ORT 1.19.2 源码**：本机代理按路径拦截 `microsoft/onnx*`（git 协议全被 reset），
   走 **gitcode.com 镜像** 拿到完整 tag 源码 + onnx 子模块（pinned SHA 精确检出）。
2. **R1 产物形态**：静态构建产物是 80+ 组件库（onnxruntime 10 + abseil 64 +
   protobuf/onnx/re2/flatbuffers/cpuinfo），非单文件 → `lib.exe` 合并为
   单一 `onnxruntime_static.lib`（onnxruntime_static.lib 放
   `lib/`，头文件放 `include/`，CMake 的 `*x64*` glob 自动选中）。
3. **MSVC 14.44 兼容**：`ort_mutex.h` 补 `#include <chrono>`（唯一源码修补，在 ort-src 侧）。
4. **/MD-/MT 冲突**：ORT 默认 /MD，op 全家 /MT → 链接 30 个 `__imp_*` 未解析。
   用 build.py 官方开关 `--enable_msvc_static_runtime` 全量重编解决。
5. **re2 陷阱**：`--skip_tests` 时 re2 目标不参与默认构建 → 补 `--target re2`
   （在 `_deps/re2-build` 子目录单独构建）后重新合并。
6. **网络**：eigen 源自 gitlab（被拦）→ 改 GitHub 官方镜像 eigenteam/eigen-git-mirror
   （同 commit），同步改 `cmake/deps.txt` 的 URL 与 SHA1；re2 等 zip 走
   `fetch_loop.py` 看门狗自动补下载（cmake 内建下载经代理不稳，curl 稳）。
7. **换模型必须删** `build/nmake-x64-Release/libop/CMakeFiles/{op_x64,op_c_api_x64}.dir/ocr_models.rc.res`，
   否则资源段还是旧模型。
8. 测试资产/字典细节见 `OCR模型基准_Dict素材6变体_20261126.md`（op-master docs）。
