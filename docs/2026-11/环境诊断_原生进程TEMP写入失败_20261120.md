# 环境诊断：原生进程无法写入 %TEMP%（2026-11-20 夜）

## 现象

新会话首次执行交接文档 §八「第一件事：确认环境能跑通」时：

```
.\build\nmake-x64-Release\tests\op_test.exe --gtest_filter="OcrEx2Test.*"
→ PASSED 1 test / FAILED 8 tests
```

8 个失败全部是同一条断言：

```
tests\ocr_ex2_test.cpp(162): error: Value of: path.empty()
  Actual: true
Expected: false
failed to build glyph bmp
```

即 `WriteGlyphBmp()` 返回空串。

## 排查过程（记录以免下次重复）

| 步骤 | 假设 | 结论 |
|---|---|---|
| 1 | cwd 不对，找不到 testdata | **否**。`OcrEx2Test` 的图是测试自己用 GDI 现画的；模型走内嵌资源（`OnnxOcrEngine::load()` 用 `LoadRes(IDR_OCR_*)`），不依赖 cwd |
| 2 | 引擎起不来 / 模型缺失 | **否**。日志有 `models loaded (v6), keys=18708`，且 `ZeroSizeRegionIsSafe` 恒 PASS |
| 3 | GDI 绘制失败（`BuildTextBmp` 返回 false） | **一度误判**。用 C++ 复写 `BuildTextBmp` 全部调用，`GetDC/CreateCompatibleDC/CreateFontW/CreateDIBSection/TextOutW` 全部成功，非白像素 2270 个 |
| 4 | `GetTempPathW` 失败 | **否**，返回 31 < MAX_PATH，正常 |
| 5 | `CreateFileW` 写 BMP 失败 | **是**。`CreateFileW(... CREATE_ALWAYS ...)` 返回 `INVALID_HANDLE_VALUE`，`GetLastError()=5 (ERROR_ACCESS_DENIED)` |
| 6 | TEMP 目录 ACL 拒绝 | **否**。ACL 里 `WENXINGDI\lc` 有 FullControl；且 `Set-Content`、`cmd /c echo > %TEMP%\x` 都能写 |
| 7 | PowerShell 与原生进程权限不同 | **是**。最小原生探针（只调 `CreateFileW`）稳定 err=5；`Start-Process` 另起进程同样 err=5 |
| 8 | 沙箱是按路径限制 | **是**。同一个 exe 改写工作区路径 `D:\AutoPro\op-master\op\workbench\tmp\` → **err=0 成功** |

## 根因

**DSH 本会话的文件沙箱拦截原生子进程对 `%TEMP%`（`C:\Users\lc\AppData\Local\Temp`）的写入**，返回 `ERROR_ACCESS_DENIED`。
PowerShell 自身的 .NET/写文件调用走另外的路径，不受影响 —— 这造成「PowerShell 能写、同路径原生进程不能写」的错觉。

> ⚠ 这不是仓库代码缺陷，也不是交接文档记录的坑之一。
> 同一台机器在非 DSH 沙箱环境下（用户自己开终端、或上一平台）跑测试是正常的，
> 所以历史上没有出现过这个现象。

## 解法（已生效）

把 `TEMP` / `TMP` 指向工作区内目录后再跑测试：

```powershell
$ws = "D:\AutoPro\op-master\op\workbench\tmp"
New-Item -ItemType Directory -Force -Path $ws | Out-Null
$env:TEMP = $ws; $env:TMP = $ws
$env:PATH = "D:\AutoPro\op-master\op\build\nmake-x64-Release\libop;" + $env:PATH
Set-Location D:\AutoPro\op-master\op
.\build\nmake-x64-Release\tests\op_test.exe --gtest_filter="OcrEx2Test.*"
```

结果：**9/9 PASSED**。随后 `workbench\test_gmplug.py` 也 **PASSED 全部校验通过（A1/A2/A3/A5/A6 零违规）**。

## 给后续会话的提醒

1. 跑 `op_test.exe` 前**先设 TEMP/TMP 到工作区**，否则所有「用 `GetTempBmpPath` 落盘」的用例都会以 `err=5` 伪失败，
   表现为大量 `path.empty()` 断言失败 —— 极易误判成代码回归。
2. `workbench\tmp\` 是中间产物目录，**不入库**。
3. 用户自己直接跑（不经 DSH）时不需要这一步；这是 DSH 会话的专属前置动作。

## 附带发现（不是问题，仅记录）

- `tests\ocr_ex2_test.cpp` 的 `BuildTextBmp` 里 `CreateFontW(...)` 之后没有判断 `font != nullptr`。
  字体创建失败时 `SelectObject(dc, nullptr)` 会静默失败，`GetTextExtentPoint32W` 得到 `cx=0`，
  图片退化为 24×64 全白 —— 用例会以「识别不到字」而非「字体缺失」的形式失败，诊断信息不友好。
  本轮**未改动**（不属于 P1 范围），列入「可能的后续」。
