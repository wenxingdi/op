## 二、缺口明细

### 2.1 COM 缺 `SetAStarMapData`（唯一的真缺口）

| C-API | COM |
|---|---|
| `OpSetAStarMap(bitmap_file, scale, ox, oy)` | `SetAStarMap` ✓ |
| `OpSetAStarMapData(w,h,bgra,size,scale,ox,oy)` | **无** |

影响：易语言侧只能传 BMP 文件路径，拿不到"内存里的障碍位图"这条路径。
（他的场景是本地文件，所以**优先级低**，但要补也就 30 分钟：DISPID 478 + idl + 实现。）

另外 3 个 `capi_only` 不是缺口：
- `OpCreate` / `OpDestroy` —— COM 侧由 `CoCreateInstance` / `Release` 承担
- `OpRequestCaptureForTest` —— 测试钩子，不进 COM
- `OpAutoOcrFromFile` —— 只是 `OcrAutoFromFile` / `OcrAutoColorFromFile` 的空颜色分发别名，COM 两个原语都有

`five_layer_matrix` 报的"op/ 实现层未转发 5 条"同属此类别名/生命周期，
与 `c_api_throw_survey` 的白名单是一回事（静态工具看不到转发关系）。

### 2.2 Python ctypes 绑定落后 40 个（**最值得补的一处**）

`bindings/python/op/api.py` 315 / `_ffi.py` 缺 40 条签名 —— 缺的**正好是 2026-11 这一批**：

| 批次 | 缺失接口 |
|---|---|
| 内存图像句柄（一期地基） | `LoadImageMem` / `LoadImageBmp` / `GetImageSize` / `GetImageData` / `CropImage` / `FreeImage` / `FreeAllImages` / `GetImageCount` / `FindStrMem` |
| 内存直操作二期 | `OcrFromMemEx2` / `OcrAutoColorFromMemEx2` / `FindPic(Ex)FromMem` / `FindColor(Ex)FromMem` / `GetColorFromMem` / `CmpColorFromMem` / `GetColorNumFromMem` / `FindMultiColor(Ex)FromMem` / `FindColorBlockExFromMem` / `YoloDetect(FromMem)(Ex2)` |
| 音频音量 | `AudioQueryPid` / `AudioQueryWindow` / `AudioGetPidFromHwnd` / `Audio(Set)GetSystemVolume` / `AudioSet{S*,}…`（8 个） |
| OCR/FindStr 增强 | `OcrEx2` / `OcrAutoColorEx2` / `OcrLastProfile` / `FindStrBatch` / `FindStrEx2` |

**这是用户可感知的缺口**：Python 脚本（含 GMAJ 那条链）现在完全用不了这批新能力。
`check_swig_sync.py` 的结论原话是「存在漂移，需重新生成」。

补法（`_ffi.py` 是声明式签名表，`api.py` 是机械包装）：
1. 从 `include/op_c_api.h` 抄 40 条签名进 `_ffi.py` 的 `signatures` 列表；
2. 在 `api.py` 按既有约定补 snake_case 方法（出参聚成返回值元组）；
3. 命名特殊表 `_PY_SNAKE_SPECIAL` 要与 `scripts/gen_api_reference.py` 同步；
4. `check_swig_sync.py` 必须回到 exit 0。

**评估：约 2 小时**（40 个 × 签名+包装+自测），属机械劳动但不适合盲写 ——
每个带 `std::wstring&` / `long*` 出参的方法都要按现有约定归位。

### 2.3 go 绑定落后 127 个

覆盖率不到 2/3，缺的更多是历史接口。**当前无 go 使用者**，判定不动，
但记录在案：将来有人用 go 就得先补这 127 个。
