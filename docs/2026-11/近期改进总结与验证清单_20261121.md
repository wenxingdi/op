## 二、新增功能（按模块）

### 1. OCR 结构化（P0，易语言刚需）

| 接口 | 层 | 作用 |
|---|---|---|
| `OpOcrEx2` | C API / COM `440` | 结构化 OCR：返回 JSON 数组，每行含 `text/conf/box/is_partial` + `chars[]`（**逐字 conf + 逐字 x1/x2**） |
| `OpOcrAutoColorEx2` | C API / COM `441` | 同上，先按颜色二值化；`find_count` 出参给命中行数 |
| `OpOcrLastProfile` | C API / COM `444` | 上一次 OCR 的**分项耗时** JSON：`det_ms/cls_ms/rec_ms/pre_ms/post_ms/boxes/lines/chars/rec_width` |

JSON 形状：
```json
[{"text":"冰晶石林","conf":0.93,"box":[120,340,268,362],"is_partial":false,
  "chars":[{"ch":"冰","conf":0.97,"x1":120,"x2":156},{"ch":"晶","conf":0.95,"x1":157,"x2":193}]}]
```
⚠ `conf`（整行，含 blank 时间平均）与 `chars[].conf`（逐字）**口径不同，不可互推**。

### 2. FindStr 增强（P1）

| 接口 | 作用 |
|---|---|
| `OpFindStrBatch` | 多目标一次传入（JSON 数组），**一次 det+rec 匹配全部目标**，N 个目标从 N 次全图 OCR 降到 1 次 |
| `OpFindStrEx2` | 单目标 + flags：1=regex 2=exact 4=ci 64=fuzzy≤1 128=fuzzy≤2 256=confirmed_only（位互斥，多给返回 -1） |

两者都返回命中片段的**字符级水平范围** `cx1/cx2`（旋转降级时退化为整行，`char_precise=false`）。

### 3. 图像句柄注册表（内存直操作一期地基）

`OpLoadImageMem` / `OpLoadImageBmp` / `OpFreeImage` / `OpFreeAllImages` / `OpGetImageSize` /
`OpGetImageData` / `OpGetImageCount` / `OpCropImage` / `OpFindStrMem`

- 句柄是字符串 `"img:<n>"`，与 `pic:<路径>` 风格一致；注册后像素不可变（多线程并发读安全）
- 上限 256 条，**满则拒绝新增（不淘汰既有）**
- 价值：调用方已有像素时省掉落盘往返（50~200ms → <5ms）

### 4. 内存直操作二期（14 个 `*FromMem`）

`OpOcrFromMemEx2` / `OpOcrAutoColorFromMemEx2` / `OpFindPicFromMem` / `OpFindPicExFromMem` /
`OpFindColorFromMem` / `OpFindColorExFromMem` / `OpGetColorFromMem` / `OpCmpColorFromMem` /
`OpGetColorNumFromMem` / `OpFindMultiColorFromMem` / `OpFindMultiColorExFromMem` /
`OpFindColorBlockExFromMem` / `OpYoloDetectFromMem` / `OpYoloDetectFromMemEx2`

坐标语义：`x1..y2` 是**图像内坐标**（相对句柄左上角），`(0,0,0,0)` = 整张图。

### 5. YOLO Ex2（过滤 / 截断）

`OpYoloDetectEx2` / `OpYoloDetectFromFileEx2` / `OpYoloDetectFromMem` / `OpYoloDetectFromMemEx2`

json_options 支持 `class_ids`（类别白名单）与 `max_results`（截断）。
语义：**`total` = NMS 后过滤前的全量条数**，`returned` = 过滤+截断后真正返回的条数。

另：`--threads=1..64` 参数（默认交给 ORT 用物理核）；端到端 **57 → 31ms**。

### 6. 音频音量（WASAPI）

`OpAudioQueryWindow` / `OpAudioQueryPid` / `OpAudioGetPidFromHwnd` /
`OpAudioGetSystemVolume` / `OpAudioSetSessionVolume` / `OpAudioSetSessionMute` /
`OpAudioSetSystemVolume` / `OpAudioSetSystemMute`

### 7. A* 内存地图

`OpSetAStarMapData`（C API + COM **DISPID 478**，`SAFEARRAY(BYTE)` 传 BGRA 障碍位图）
此前 COM 只有文件版 `SetAStarMap`，易语言拿不到"内存里的障碍图"。

### 8. 三层绑定

| 层 | 变化 |
|---|---|
| C API | 353 导出，覆盖 **353/353** |
| COM | 350 方法（新增 DISPID 460~478 共 19 个） |
| Python ctypes | `api.py` 354 个方法（补齐 39 个），`_ffi.py` 同步 |
| SWIG | `pyop.py` 368 个 def（补齐 38 个），`_pyop.pyd` 编译链接通过 |
| go | 补 126 个方法（`go build` / `go test` 全绿） |

## 三、修掉的真缺陷（这几条最值得你二次验证）

| # | 缺陷 | 后果 | 反向验证 |
|---|---|---|---|
| 1 | **MIDL 把 idl 注释里的中文当续行，吞掉 10 个 COM 方法** | `LoadImageMem`/`OcrEx2`/`DecodeQRCode`/`HttpGet`/`FindStrBatch`/`JsonIsValid`/`OcrAutoColor`/`OcrLastProfile`/`OcrFromMemEx2`/`CvMatchTemplateRot` **从来没进过类型库** → 易语言调它们报 `DISP_E_UNKNOWNNAME` | 修复前后同一探针 FAILS=2 → 0 |
| 2 | `OcrEx2` / `OcrAutoColorEx2` 的 retval 标错（`[out] BSTR*` 无 retval） | 易语言拿不到 OCR 文本，返回值是 HRESULT | 断言 `pVarResult` 是 `VT_BSTR` |
| 3 | 音频 4 个 setter 返回值**语义整体反转** | 成功返回 0（被判失败）、失败返回 -5（负数被当成功） | 改回透传 → 3 条用例变红 |
| 4 | `OpTerminateProcessTree` 判据不可靠 | 调用方自己持有进程句柄时，**杀掉了却返回 0** | 改回旧判据 → 用例变红 |
| 5 | YOLO 推理写死单线程 | 纯推理慢 4.8 倍（端到端 1.8 倍） | 改回写死 → ratio 0.99，基准脚本 exit=1 |
| 6 | C API 异常护栏 7 条未覆盖（含 `OpDestroy`） | 析构链异常穿过 `extern "C"` = `std::terminate`（退出必崩） | 普查 7 → **0** |
| 7 | x86 上 `op_i.h` 更新不重编 COM 源 | 32 位 DLL 的 vtable 少 10 个方法 → 调新方法直接 `0xC0000005` | 删 obj 重编后 32 位双路径 PASS |

> 1 和 2 是同一批 COM 方法的问题；如果你只用 C API / Python，影响不到你；
> **如果你用易语言调 COM，这两个必须复验**。

## 五、已知限制（别当 bug 报）

| 项 | 现状 |
|---|---|
| OCR 全图耗时 | 14 行 **645ms**（rec 占 77%，`PP-OCRv6_small` + 批量 + 4 线程已到模型成本）；**单行 47ms** |
| 线程数对 OCR 无效 | 4→8 线程 rec 448→445ms，加线程没意义 |
| OCR 多档位切换 | 实测 8/8 成功，但每次切档要重建引擎（约 1 秒，内存换时间） |
| `OpKeyPressHotkey` | 测试只覆盖**拒绝路径**（合法组合会真发按键，测试不制造副作用） |
| `OpAutoOcrLine` | 只证"分发不崩"，分支差异证明不了（废弃别名，建议直接用 `OpOcrAutoColor*`） |
| WGC 3 项失败 | `WgcTest.Maximi*`：日志明示"进程内曾 SEH fault 后跳过 WGC 绑定"，环境项，与本轮改动无关 |
| `go vet` | 1 条既有 `unsafe.Pointer` 警告（`dll_windows.go:566`），未修 |
| `bin\x86` vs `bin\x64` | 32 位宿主用 `bin\x86`（带 32 位 onnxruntime）；`bin\x64` 里的 x86 件仅供注入 |
